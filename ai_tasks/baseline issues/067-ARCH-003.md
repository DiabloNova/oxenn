**Type:** Additional source-to-schema contract defect found during architecture-aligned revalidation

**Disposition:** CONFIRMED STATIC CONTRACT MISMATCH AT AUDITED MAIN BASELINE; migration/runtime verification still required

## 1. Problem and evidence

The AI-intelligence domain types and repository SQL use column and entity contracts that do not align with the canonical Drizzle schema in `database/schema/index.ts`.

### Brands

- Domain `Brand` expects `website` and optional `description`.
- Canonical `brands` table stores `canonical_domain`, `aliases`, `industry`, and `target_markets`; it does not define the same `website`/description shape.
- `BrandRepository` in `src/features/ai-intelligence/repositories/index.ts` is entirely backed by the process-local `db.brands` map and performs no PostgreSQL persistence.

### Pages

- Domain `Page` expects `statusCode`, `indexability`, and `description`.
- Canonical `pages` schema uses `http_status`, `meta_description`, `content_type`, `content_hash`, `word_count`, `canonical_url`, and other crawl fields; it does not declare `status_code` or `indexability`.
- `PageRepository` selects and writes `status_code`, `indexability`, and `description` columns. Its SQL contract therefore does not match the inspected canonical schema.

### Diagnostic findings

- Domain `DiagnosticFinding` expects `websiteId`, `category`, `code`, `explanation`, and `affectedResource`.
- Canonical `diagnostic_findings` schema stores `domain`, `finding_type`, `severity`, `confidence`, `title`, `description`, `evidence`, `recommendation`, `impact_score`, and `status`; it does not define the repository's `website_id`, `category`, `code`, `explanation`, or `affected_resource` columns.
- `PostgresDiagnosticFindingRepository` queries and writes the latter set of columns, then returns process-local map values rather than database rows.

The same column definitions were also found in the initial checked-in migration `database/drizzle/0000_reflective_loa.sql`: `pages` has `http_status` and `meta_description` but not `status_code` or `indexability`; `diagnostic_findings` has `domain` and `finding_type` but not the repository's `website_id`, `category`, `code`, `explanation`, or `affected_resource`; and `brands` stores `canonical_domain` rather than the domain type's `website` field. This confirms the mismatch is present in the checked-in initial migration as well as the Drizzle schema. It does not assert that the live database has been queried or that all later migrations have been replayed.

## 4. Root cause

The domain model, repository SQL, and canonical persistence schema have evolved as parallel contracts without a single enforced mapping or generated consistency check. The in-memory fallback hides the incompatibility by allowing application paths to operate against process-local objects even when the corresponding SQL reads/writes fail or return different shapes.

## 5. Recommended remediation

Do not patch individual column names in isolation. First produce an explicit crosswalk for Brand, Website, Page, and DiagnosticFinding:

1. Compare domain type, repository interface, every SQL statement, canonical Drizzle schema, active migrations/snapshots, and all consumers.
2. Decide the authoritative business meaning for each field. In particular, determine how `Page.indexability` is derived/stored and whether `DiagnosticFinding.websiteId/code/affectedResource` are required domain attributes or should be represented through a normalized evidence/resource relation.
3. Choose one canonical model: either evolve the schema through reviewed migrations to support the approved domain contract, or revise domain/repository contracts to match the canonical schema. Do not maintain two incompatible shapes.
4. Define explicit, typed row-to-domain and domain-to-row mappers. Parse timestamps, nullable values, arrays, JSONB, enums, and numeric fields safely; reject invalid persisted rows instead of silently coercing them.
5. Add tenant-scoped SQL predicates even where RLS also applies, and preserve soft-delete semantics.
6. Make PostgreSQL the production source of truth. Keep in-memory repositories only as explicit test/demo adapters.
7. Ensure INSERT/UPSERT returns the persisted row so a conflict cannot leave the caller holding a newly generated ID that differs from the database row ID.
8. Only after the crosswalk is approved, address the read-path defect in Finding 004 (SRC-004) by returning mapped `rows`, not maps.

## 7. Risks and non-goals

- A direct mapper that silently drops `indexability`, website relationships, diagnostic codes, or resource identity would lose domain semantics.
- A schema migration must not be created until existing data, constraints, active migration history, and rollback strategy are understood.
- Do not infer live database schema from the checked-in Drizzle model alone.
- Do not retain production process-local fallback behavior as a compatibility path.
- No database, source, or migration changes are made by this specification.

## 8. Verification plan

- Contract tests for every row mapper in both directions, including nullability, timestamps, JSONB, arrays, and invalid persisted values.
- PostgreSQL integration tests on a fresh database created from the active migration chain.
- Populated-data migration tests for any schema evolution.
- Read-after-write and process-restart tests for Brand, Website, Page, and DiagnosticFinding.
- Conflict/upsert tests proving returned IDs and version values match persisted rows.
- Two-tenant tests proving reads, writes, soft deletes, and joins remain tenant-scoped.
- Call-site regression tests for all consumers of the affected domain types.

## 9. Acceptance criteria

- Domain types, repository interfaces, SQL, canonical schema, active migrations, and snapshots agree.
- Every database read maps actual returned rows into domain entities.
- Every production write is durable and returns the canonical persisted entity.
- No production repository depends on process-local maps.
- Tenant predicates and RLS remain effective.
- All data migrations are versioned, replayable, and tested against fresh and representative populated fixtures.
