# 051 — SRC-005: Tenant-facing actions automatically seed demo records as if they were real customer data

## Source
- Finding ID: `SRC-005`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: as recorded in the static source audit; runtime/deployment conditions remain subject to revalidation

## Problem
Several tenant-facing SEO/AEO/brand/citation/site-architecture actions create fixed sample websites, pages, brands, source domains, citation occurrences, or graph relationships when repository reads appear empty. Some synthetic technical SEO signals are marked `isMeasured: true` and persisted to tenant tables. The behavior can repeat because of SRC-004's process-local reads.

## Evidence
- `technical-seo.ts:168-264` seeds `secure-site.com` and persists mock signals; helper marks them measured.
- AEO content service uses fixed sample page text and Rasha Gostar identity.
- Brand Intelligence creates sample brand/associations.
- Citation Intelligence seeds fixed domains/occurrences.
- Site Architecture creates synthetic pages/link data.

## Affected files and paths
- Technical SEO, AEO, brand, citation, and site-architecture server actions/services.
- Repository write paths and tenant data tables.

## Impact
Empty customer workspaces can receive synthetic records and metrics that appear to be real observations. This corrupts customer data, undermines trust, and can repeatedly seed or overwrite records.

## Recommended solution
1. Remove automatic sample seeding from production tenant actions.
2. If demo content is required, use a separate explicit demo workspace/fixture adapter that cannot write to real tenant-owned production tables.
3. Mark every synthetic value as MOCK/DEMO and never set measured/evidence-backed flags on generated values.
4. Require source evidence, timestamp, method, provider/model, mode, and tenant identity before storing a real observation.
5. Reconcile with the LIVE/MOCK/HYBRID contract in the AI evidence layer and DOC-005.
6. Add tests proving an empty real tenant remains empty and demo mode cannot cross tenant boundaries.

## Architecture alignment
The product architecture depends on evidence-backed assessments and explicit provenance. Synthetic demo data must never be represented as customer measurements or mixed with LIVE records.

## Verification criteria
No production action seeds fixtures; mock data is visibly marked and isolated; measured claims have source evidence; empty workspaces remain empty.
