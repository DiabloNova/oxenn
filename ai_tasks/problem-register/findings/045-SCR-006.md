# 045 — SCR-006: Developer shell helpers are brittle and root reconnaissance wrapper references the wrong paths

## Source
- Finding ID: `SCR-006`
- Original audit: `ai_tasks/scripts-folder-audit.md`
- Status: as recorded in the source audit; dependent behavior remains subject to revalidation

## Problem
The route helper iterates over unquoted command substitution, which can split paths containing whitespace, and infers UI states from literal keyword matches in page files. The signature helper hardcodes an old auth source path. Both helpers live under `scripts/dev-tools/`, while the root `update_recon.sh` invokes root-relative helper paths. This refines RF-001: the helper scripts exist, but not at the paths the wrapper expects.

## Evidence
- `scripts/dev-tools/get_routes.sh:6-19` uses unquoted `for file in $(find ...)` and shallow text heuristics.
- `scripts/dev-tools/get_signatures.sh:5` hardcodes `src/app/actions/auth.ts`.
- Helpers exist under `scripts/dev-tools/`, not repository root.
- `update_recon.sh` invokes `./get_routes.sh` and `./get_signatures.sh`.

## Affected files and paths
- `scripts/dev-tools/get_routes.sh`
- `scripts/dev-tools/get_signatures.sh`
- `update_recon.sh`
- Current route and action source tree.

## Impact
The wrapper cannot reliably locate the helpers; route discovery can omit or misclassify files; signature output can become stale as source paths change.

## Recommended solution
1. Resolve helper paths relative to the wrapper's own location and invoke the actual nested paths.
2. Use null-delimited file discovery and quoted iteration so spaces and unusual filenames are handled safely.
3. Replace grep-only UI-state inference with a parser or explicit route inventory where practical; otherwise label heuristic output as approximate.
4. Discover action/signature source paths from current repository structure rather than hardcoding a single obsolete file.
5. Validate generated output and propagate failures before replacing any existing report (coordinate with RF-001).
6. Add tests for paths with spaces, missing source files, renamed route modules, and invocation from another working directory.

## Architecture alignment
Repository reconnaissance is deterministic tooling. It should consume current source structure and produce provenance-stamped evidence without becoming a competing source of truth.

## Verification criteria
Wrapper finds the helpers from any working directory; file paths are safely handled; generated routes/signatures match current source; failures do not overwrite reports.
