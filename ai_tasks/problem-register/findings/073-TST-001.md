# 073 — TST-001: Most tracked test files are outside configured Vitest projects

## Source
- Finding ID: TST-001
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
Vitest discovers only tests/unit, tests/db, and tests/ui, while the repository contains many tests under tests/features, tests/services, tests/actions, tests/scripts, and tests/isolation. Package scripts do not invoke most custom run-all.ts suites; the acquisition script targets only a unit-test directory.

## Evidence
Evidence: vitest.config.ts limits project includes; tree contains 19 feature tests, 24 service tests, and other suites; package scripts do not invoke most custom suites.

## Affected files and paths
vitest.config.ts, package.json scripts, tests/features, tests/services, tests/actions, tests/scripts, tests/isolation.

## Impact
A green standard test command may leave a substantial tracked test corpus undiscovered, so regression coverage is weaker than the repository structure suggests.

## Recommended solution
Inventory every test and assign an explicit owner/project/command. Move compatible tests into supported Vitest projects or register dedicated scripts. Ensure CI invokes required domain suites and reports discovered, executed, skipped, and excluded tests. Retire obsolete tests only with documented coverage migration. Avoid one giant project that obscures integration prerequisites.

## Architecture alignment
The architecture needs domain/application/infrastructure contracts with reliable regression gates. A test that is not invoked is not an effective gate.

## Verification criteria
Every retained test has a documented runner; required suites run in CI; excluded tests have explicit rationale; empty/skipped suites are visible.
