# 037 — PUB-004: Large logo-horse.png is not used by the inspected landing header/footer

## Source
- Finding ID: `PUB-004`
- Original audit: `ai_tasks/public-folder-audit.md`
- Status: as recorded in the original public-folder audit; incomplete source-search limitations are preserved

## Problem
`public/logo-horse.png` is a 1208×1302 RGBA image of 1,147,252 bytes, representing about 45.8% of the public subtree's total bytes. The inspected landing header and footer use an inline SeorchableLogo SVG instead. No direct use of logo-horse.png was established in those components, but repository-wide dynamic references were not exhaustively proven absent.

## Evidence
- File size/dimensions/format were inspected.
- Landing header/footer render inline SeorchableLogo SVG.
- GitHub source search was incomplete; global non-use is not asserted.

## Affected files and paths
- `public/logo-horse.png`
- Landing header/footer and any other image consumers.

## Impact
If unused, the asset adds significant public payload and maintenance noise. If used elsewhere, optimizing/removing it without tracing the consumer could break a page or report.

## Recommended solution
1. Identify the asset's intended product/UI owner and trace static, dynamic, CMS, and URL-based references.
2. If used, resize to actual rendered dimensions, optimize metadata/compression, and consider SVG or modern image formats where the artwork permits.
3. If legacy/unused, remove only after a complete reference check and separate cleanup approval.
4. Preserve original source artwork and provenance outside the runtime asset path if needed.

## Architecture alignment
Public assets should be purposeful and optimized for their actual frontend consumers; do not remove assets based on incomplete search evidence.

## Verification criteria
Every retained large asset has a documented consumer and optimized delivery path; confirmed-unused assets are removed only after approval.
