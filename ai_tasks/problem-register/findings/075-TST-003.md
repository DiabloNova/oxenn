# 075 — TST-003: Tenant-table verification lacks an independent completeness oracle

## Source
- Finding ID: TST-003
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
The tenant-table unit test checks that the runtime list matches the set returned by verifyTenantTables, but its hardcoded required list omits the five organization-owned junction tables. The verification script itself derives expected tables from snapshot entries that already have RLS policies, so both sides can agree while omitting the same tables.

## Evidence
Evidence: tests/unit/core/tenant-context/tenant-tables.test.ts:10-18 compares two derived sets; :20-42 hardcoded list omits five; verifyTenantTables derives from policy-bearing snapshot entries.

## Affected files and paths
Tenant-table unit tests, verification script, canonical ownership inventory, RLS policy metadata.

## Impact
A green test can prove consistency between two incomplete sets, not completeness of tenant-owned tables.

## Recommended solution
Create an independent, reviewed expected ownership inventory that does not derive from RLS policy presence. Assert every tenant-owned table appears in runtime metadata and separately assert policy/migration coverage. Add mutation tests that remove a known tenant table from generated output and ensure the suite fails.

## Architecture alignment
Contract & Provenance Gates require independent checks; the implementation under test cannot define its own expected truth.

## Verification criteria
Omitting any known tenant-owned table causes a failure; policy absence is reported separately; tests use independent expected data.
