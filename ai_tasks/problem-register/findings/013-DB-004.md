# 013 — DB-004: Active database migrations do not contain the archived crawl-queue functions claimed as absorbed

## Source
- Finding ID: `DB-004`
- Original audit: `ai_tasks/database-folder-audit.md`
- Status: active migration absence confirmed; application-level replacement remains unknown

## Problem
The archived migration `database/archive/migrations-legacy/0004_crawl_acquisition.sql` defines three PostgreSQL `SECURITY DEFINER` functions—`claim_crawl_jobs`, `recover_expired_crawl_jobs`, and `complete_crawl_job_if_lease_owner`. The archive README says they were absorbed into the canonical schema/migration chain, but static inspection of the active schema and migrations `0000`–`0013` found no corresponding definitions.

This does not yet prove that the crawl queue is broken: source code may implement equivalent transactional behavior.

## Evidence
- The three functions exist in `database/archive/migrations-legacy/0004_crawl_acquisition.sql`.
- The archive mapping README claims they were absorbed into the canonical schema and migration.
- No equivalent function definitions were found in the active migration chain or canonical schema during the audit.
- The archive explicitly warns that legacy migrations are historical and must not be executed.

## Affected files and paths
- `database/archive/migrations-legacy/README.md`
- `database/archive/migrations-legacy/0004_crawl_acquisition.sql`
- Active schema and migration chain under `database/schema/` and `database/drizzle/`.
- Crawl dispatcher and worker call sites in `src/`.

## Impact
The repository's documentation does not reliably identify the active implementation of crawl claiming, lease recovery, and lease-owner completion. This creates a risk that developers rely on archived SQL or assume concurrency guarantees that are not actually present.

## Recommended solution
1. Trace the active dispatcher, worker, repository, and transaction call sites for claim, lease recovery, and completion.
2. Compare their actual SQL/locking behavior with the archived functions' invariants: atomic claim, lease ownership, expiry recovery, and owner-checked completion.
3. If equivalent application-level transactions exist, document the real implementation and its concurrency/security guarantees; update the archive README to say the functions were replaced, not absorbed into the active schema.
4. If behavior is missing, design the narrowest supported implementation in the current architecture. Prefer an explicit repository/transaction contract or a reviewed database function with least privilege; do not restore historical SQL without security review.
5. Add concurrency and crash-recovery tests for competing workers, expired leases, duplicate completion, and stale lease owners.
6. Keep archived migrations immutable and ensure all verification commands explicitly target the active migration chain.

## Architecture alignment
Crawl acquisition is a bounded execution workflow. Durable job state and lease ownership belong to the persistence/worker contract; they must not be inferred from old archive files or hidden process-local state.

## Verification criteria
- One active, documented implementation exists for claim, recovery, and completion.
- Only the current lease owner can complete a job.
- Concurrent workers cannot claim the same unexpired job.
- Expired leases recover deterministically.
- Tests prove behavior using the active database/runtime path.
- No historical archive migration is executed.
