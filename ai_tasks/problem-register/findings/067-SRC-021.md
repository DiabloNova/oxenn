# 067 — SRC-021: API-key settings UI and public API middleware are not connected to a usable API-key flow

## Source
- Finding ID: SRC-021
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
Settings shows a hardcoded sc_live value and a local-only success state. ApiService generates a different seo_ prefix. No server actions create/revoke keys and no route invokes withPublicApi, so the middleware/quota path protects no endpoint.

## Evidence
Evidence: dashboard settings hardcodes key; ApiService uses another prefix; no create/revoke actions or middleware consumers were found.

## Affected files and paths
Settings page, API-key service/repository/schema, public API middleware, quota handling, route inventory.

## Impact
Users cannot create, rotate, revoke, or use the advertised key. UI claims a capability not connected to backend.

## Recommended solution
Decide whether public API is MVP scope. If approved, define one key format and lifecycle: create, one-time reveal, hash-at-rest, metadata listing, rotate, revoke, audit. Wire authenticated server actions to durable storage and apply middleware to real routes with entitlement/quota enforcement. If deferred, remove fake key and disable control accurately. Test key lifecycle, scope, revocation, and over-quota behavior.

## Architecture alignment
API keys are an external access surface governed by organization identity, authorization, and commercial entitlements.

## Verification criteria
Real keys can be created/revoked or feature is explicitly disabled; secrets are hashed/scoped; routes enforce quotas.
