# 058 — SRC-012: Text and ingestion endpoints lack server-side payload and result limits

## Source
- Finding ID: `SRC-012`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: as recorded in the static source audit; runtime/deployment conditions remain subject to revalidation

## Problem
Several document/text ingestion, chunking, sentiment, and RAG query endpoints accept unbounded or weakly bounded input. Metadata is unrestricted, chunk size has no upper ceiling, and retrieval limits accept any positive value. A 5 MB UI file check is client-side only and does not protect direct API callers.

## Evidence
- Document ingestion accepts text with a minimum but no maximum and unrestricted metadata.
- AI chunk/sentiment routes accept unbounded text; chunk size has no maximum.
- RAG query routes accept positive result limits without a maximum.
- UI 5 MB file check is client-side only.

## Affected files and paths
- Document ingestion API/server action.
- AI chunk and sentiment APIs.
- RAG query API/server action.
- Shared request schemas and provider usage limits.

## Impact
Direct callers can cause high memory/CPU/provider spend/database load by submitting oversized text/metadata, huge chunks, or excessive retrieval limits.

## Recommended solution
1. Define shared server-side schemas with maximum request body, text length, metadata bytes/depth, chunk size, overlap, and retrieval result count.
2. Enforce limits before parsing or retaining large bodies where possible, including streaming upload caps.
3. Add per-tenant concurrency, token, and cost budgets at the operation boundary.
4. Return stable validation errors that identify the violated limit without exposing internals.
5. Keep client-side checks as UX only; never rely on them for security/resource control.
6. Test direct API calls that bypass the UI, including boundary values and oversized payloads.

## Architecture alignment
Resource budgets are part of the evidence-acquisition and AI execution contracts. Limits must be enforced server-side and tied to durable entitlements.

## Verification criteria
Oversized payloads are rejected before expensive work; metadata and result limits are bounded; direct callers cannot bypass UI limits.
