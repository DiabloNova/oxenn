# 079 — TST-007: Crawl state-machine test barely asserts the allowed transition contract

## Source
- Finding ID: TST-007
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
The test iterates the status matrix but asserts only that transitions rejected by canTransition throw. It checks one allowed transition and does not independently declare the expected allowed transition set. The implementation predicate effectively supplies its own expected result.

## Evidence
Evidence: tests/unit/features/acquisition/state-machine.test.ts:11-24 loops over canTransition; only a few explicit transitions are asserted.

## Affected files and paths
Crawl state machine domain module and its unit tests.

## Impact
A regression that incorrectly rejects a valid transition may remain undetected; the test checks internal consistency more than the domain contract.

## Recommended solution
Define the full allowed transition matrix as independent test data derived from the approved domain lifecycle. Assert every valid transition succeeds and every invalid transition fails, including terminal/cancelled/retry cases. Include state transition versioning if the lifecycle contract evolves. Avoid importing the implementation predicate to generate expected outcomes.

## Architecture alignment
The deterministic execution lifecycle depends on explicit domain state transitions and should not be delegated to orchestration framework defaults.

## Verification criteria
Every state pair has an independently expected result; allowed and rejected transitions are exhaustively asserted.
