# 035 — PUB-002: Sample PDF is a broken placeholder and report export UI does not download or generate it

## Source
- Finding ID: `PUB-002`
- Original audit: `ai_tasks/public-folder-audit.md`
- Status: as recorded in the original public-folder audit; incomplete source-search limitations are preserved

## Problem
The public PDF is an 866-byte single-page text stub with an incorrect startxref pointer. The report page handler only waits and updates a success state; it neither downloads this PDF nor generates a report, despite UI copy claiming that it generates and downloads a PDF.

## Evidence
- The public PDF parser reports an incorrect startxref pointer and one-page placeholder content.
- The report page handler uses a timeout/success-state update only.
- No download or report-generation action is implemented in the inspected handler.

## Affected files and paths
- Public sample PDF asset.
- Report page component and export handler.
- Any future report-generation service and download endpoint.

## Impact
Users may be told that a report was generated/downloaded when no file was produced. The sample asset itself may also fail to open in PDF readers.

## Recommended solution
1. Treat the current asset as a non-production sample and label it accordingly; do not represent it as a generated customer report.
2. Decide whether PDF export is within the approved MVP scope before building it.
3. If approved, define a server-side report contract using persisted, evidence-backed report data; generate a valid PDF with a maintained toolchain and correct metadata.
4. Return an authenticated, authorization-checked download or short-lived file reference; do not fabricate a success state on the client.
5. Ensure generation failures are visible and do not mark an export as complete until the file is durable and retrievable.
6. Add tests for valid PDF structure, tenant authorization, content correctness, download headers, and failure states.
7. Until the real flow exists, disable or clearly mark the export action as unavailable/sample-only.

## Architecture alignment
Reporting is a shared capability and must use evidence-backed persisted data with tenant authorization. Client-side state is not proof that an external artifact was generated.

## Verification criteria
The export button either remains explicitly unavailable or produces a valid tenant-authorized PDF whose contents match the selected report; failure never appears as success.
