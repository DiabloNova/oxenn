# 080 — TST-008: Inngest integration test treats a named placeholder as scheduled-work coverage

## Source
- Finding ID: TST-008
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
The test checks only that the scheduled function exists and has the name scheduled-monitoring-placeholder. It does not exercise schedule dispatch, monitoring, crawl execution, retries, persisted snapshots, or alerts.

## Evidence
Evidence: tests/unit/inngest/inngest-integration.test.ts:12-17 asserts function existence/name only; SRC-019 confirms the function is a no-op.

## Affected files and paths
Inngest scheduled monitoring function and integration test; durable schedule/worker infrastructure.

## Impact
The test remains green while monitoring is a no-op and can create false confidence that scheduled work is implemented.

## Recommended solution
Replace the placeholder existence assertion with integration tests for actual due-work loading, idempotent dispatch, worker execution, persisted evidence, retry/failure, and alert creation. If scheduled monitoring is deferred, test that the UI/API reports it unavailable and remove any success claim.

## Architecture alignment
Continuous improvement requires observable execution and verified outcomes; registration is not execution.

## Verification criteria
A successful test demonstrates a real monitoring cycle or explicitly verifies the feature is disabled; no placeholder is treated as coverage.
