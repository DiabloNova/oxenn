## Revalidated root cause
The production email sender was a placeholder whose `send()` method always failed. The old example environment guidance also implied that a non-empty provider variable selected a working implementation. Registration and verification callers swallowed asynchronous send failures, and workspace invitations returned success while the send promise was still outstanding; when sender creation failed, the invitation flow could expose a raw token as a fallback.

## Implementation
- Replaced the production placeholder with a real Nodemailer SMTP sender. The supported production provider is explicit (`EMAIL_PROVIDER=smtp`); unsupported or missing providers fail closed.
- Validates SMTP host, port, sender address, paired credentials, secure-mode setting, and minimum TLS version before use. Submission uses explicit timeouts and requires the SMTP server to accept the recipient before the send operation resolves.
- Provides safe HTML/text templates for email verification and password reset. Subject line CR/LF characters are removed; external/provider errors are not logged or exposed to callers. The repository has no workspace-invitation acceptance route, so workspace-invitation email is explicitly rejected in both development and production rather than sending a known-broken link.
- Added an application-origin link builder. Production requires a configured HTTPS origin; no production localhost fallback or external/protocol-relative action path is allowed.
- Registration awaits verification-mail submission and surfaces the outcome for the newly created account. Public resend remains enumeration-safe; its response does not disclose account existence or provider health. Existing delivered verification links remain valid until a replacement message is accepted and activated atomically.
- Password-reset submission is awaited while preserving the public enumeration-safe response.
- The workspace-invitation action awaits email submission and revokes an undelivered pending invitation; the raw token is never returned as a fallback. Because the acceptance route does not exist, the email adapter rejects this template, so this feature remains unavailable until separate `SRC-016` work adds the acceptance UI.
- Updated `.env.example` with non-secret SMTP settings and explicit production-origin guidance.
