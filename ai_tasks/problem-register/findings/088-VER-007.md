# 088 — VER-007: Historical C06 runner inventory no longer matches current package scripts and repository paths

## Source
- Finding ID: VER-007
- Original audit: ai_tasks/verification-folder-audit.md
- Status: historical evidence or verification gap as described in the original audit; unsafe probes are not authorized for execution

## Problem
The old runner inventory says a legacy acquisition run-all.ts is invoked by pnpm test:acquisition and lists a monitoring test path that no longer exists. Current package.json maps test:acquisition to a Vitest unit project, while the legacy integration runner has no dedicated script.

## Evidence
Evidence: phase-7/c06 inventory claims old invocation/path; current package.json test:acquisition targets tests/unit/features/acquisition; tests/services/monitoring path is absent; OX-102 records its migration/deletion.

## Affected files and paths
verification/phase-7/c06-mp1-runner-inventory.md, package.json, current tests tree and CI.

## Impact
Operators may believe the wrong suite ran or treat a historical inventory as current test provenance.

## Recommended solution
Preserve the old inventory as historical. Create a current runner inventory from package scripts, Vitest projects, CI workflow commands, and standalone test entry points. Record exact paths and whether each suite is required, optional, skipped, or retired. Validate inventory in CI when package scripts or test paths change.

## Architecture alignment
Every domain contract suite needs an explicit discoverable execution path and reliable CI evidence.

## Verification criteria
Current runner inventory matches package scripts and CI; stale paths are labeled historical; changes to runner wiring update the inventory.
