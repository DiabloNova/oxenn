# 072 — SRC-026: Citation share percentages are calculated before sample occurrences are seeded

## Source
- Finding ID: SRC-026
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
Citation Intelligence calculates brandShare, competitorShare, and otherShare from the initial occurrence set. If empty, the action seeds sample rows and reloads them but does not recalculate percentages, so returned rows and shares can contradict one another.

## Evidence
Evidence: citation-intelligence.ts calculates shares before seeding; reloads occurrences after seeding without recomputation.

## Affected files and paths
Citation Intelligence action/service, occurrence repository, dashboard metrics.

## Impact
First dashboard load can display seeded rows with percentages calculated from an empty set, and demo records may be mistaken for real measurements.

## Recommended solution
Remove implicit production seeding (SRC-005). In explicit demo mode, compute shares from final demo rows and label MOCK. In production, derive all metrics from the final persisted evidence-backed occurrence set using one shared pure aggregation function. Test empty, demo, populated, zero-denominator, and rounding cases.

## Architecture alignment
Citation shares are evidence-derived metrics and must use the same validated occurrence snapshot as displayed rows.

## Verification criteria
Returned percentages match returned rows; production contains no implicit fixtures; demo mode is explicit.
