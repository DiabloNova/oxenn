# 064 — SRC-018: Email verification is hard-disabled in application code

## Source
- Finding ID: SRC-018
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
Authentication actions set REQUIRE_EMAIL_VERIFICATION=false, so login does not reject unverified accounts even though registration/verification flows send verification links. Whether verification is mandatory is a product/security policy decision that must be explicit.

## Evidence
Evidence: auth.ts defines the false constant and login consults it before rejecting unverified accounts.

## Affected files and paths
Authentication actions/config, verification token flow, email provider and security policy docs.

## Impact
Accounts can authenticate without proving control of the email address, potentially allowing mistaken or malicious registration of another person's address.

## Recommended solution
Obtain explicit product/security policy. If verification is required, make it environment-aware with a secure production default; use single-use hashed tokens with expiry and bind them to the account/email version. Define resend, email-change, expiry, and recovery behavior. Block prohibited sensitive actions for unverified accounts. Test provider failure and login-before-verification.

## Architecture alignment
Identity assurance is an explicit security policy; provider availability must not silently bypass it.

## Verification criteria
Approved policy is documented and enforced; token lifecycle is safe; unavailable email does not create a verification bypass.
