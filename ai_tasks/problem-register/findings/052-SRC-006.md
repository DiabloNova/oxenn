# 052 — SRC-006: Audit and analysis endpoints return synthetic scores without disclosing mock mode

## Source
- Finding ID: `SRC-006`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: as recorded in the static source audit; runtime/deployment conditions remain subject to revalidation

## Problem
Multiple routes/services return hardcoded or randomized scores, page counts, benchmark values, or progress messages without making the provider/crawl calls implied by the UI. Examples include the Free Audit timer/random score, competitive scores derived from URL strings, technical optimization metrics using Math.random, hardcoded analytics summaries, and fixed premium competitor values.

## Evidence
- `src/services/auditService.ts` simulates progress and uses `Math.random`.
- Competitive analysis route scores URL strings without fetching competitor content.
- Technical optimization route reports requested page count and random metrics.
- Analytics summary returns hardcoded values.
- Premium audit uses fixed benchmark values.

## Affected files and paths
- Free audit service/UI.
- Competitive analysis route.
- Technical optimization route.
- Analytics summary and premium audit routes.

## Impact
Users can mistake synthetic rankings, page counts, benchmark values, and performance metrics for measured results. URL-derived pseudo-scores are persisted as analysis without source evidence.

## Recommended solution
1. For each endpoint, either implement the real evidence collection and calculation or explicitly expose a DEMO/MOCK mode.
2. Do not persist synthetic output as a production observation or use it in customer-facing ROI/competitiveness decisions.
3. Separate measured values, estimates, and unavailable/unknown values in response contracts.
4. Require source URLs, fetch timestamps, evidence references, method/model versions, and provenance for measured outputs.
5. Remove fabricated progress messages that imply provider work that did not occur.
6. Add contract tests proving production mode fails closed when required providers/data are missing and mock mode is visibly labeled.

## Architecture alignment
Product assessment and reporting must be grounded in the Product Evidence Graph and explicit LIVE/MOCK/HYBRID provenance. An LLM-generated or heuristic score is not itself evidence.

## Verification criteria
Every production metric is traceable to source evidence and calculation version; synthetic mode is explicit and cannot be persisted as live data; UNKNOWN is not converted to zero.
