# 087 — VER-006: Historical RLS matrix runner has fixed database targeting without identity verification

## Source
- Finding ID: VER-006
- Original audit: ai_tasks/verification-folder-audit.md
- Status: historical evidence or verification gap as described in the original audit; unsafe probes are not authorized for execution

## Problem
The old RLS matrix runner hardcodes localhost:5432 and database oxenn_test with embedded test-role credentials. It wraps test operations in transactions and attempts rollback, which is a positive control, but it does not verify the server/database identity before connecting.

## Evidence
Evidence: phase-0/run_rls_matrix.js hardcodes host/port/database and local role credentials; per-operation rollback exists; no explicit target identity check.

## Affected files and paths
verification/phase-0/run_rls_matrix.js, database test infrastructure and credentials.

## Impact
A same-named local database could be targeted unintentionally. Rollback is useful but does not establish that the selected database is disposable or correctly isolated.

## Recommended solution
Do not execute this historical runner. Mark it HISTORICAL_ONLY / DO NOT RUN. If coverage is needed, replace it with a maintained integration suite that verifies database identity, role privileges, schema version, and disposable status before connecting; load secrets from protected test configuration; use transaction rollback plus fixture cleanup; and emit exact target identity without credentials.

## Architecture alignment
Database isolation verification is itself a privileged operation and must be gated by a verified disposable target.

## Verification criteria
Historical runner remains unused; any replacement proves target identity and safety before SQL; credentials are not embedded or logged.
