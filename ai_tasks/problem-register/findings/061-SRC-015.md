# 061 — SRC-015: Crawl dispatcher calls SQL functions absent from the active migration chain

## Source
- Finding ID: SRC-015
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
The PostgreSQL dispatcher repository calls claim_crawl_jobs, recover_expired_crawl_jobs, and complete_crawl_job_if_lease_owner. These functions are only in archived legacy SQL and absent from active migrations 0000–0013. A fresh database created only from active migrations therefore lacks worker dependencies.

## Evidence
Evidence: dispatcher-repository.ts invokes all three functions; DB-004 confirms absence from active schema/migrations and presence only in archive.

## Affected files and paths
Dispatcher repository, active migrations/schema, crawl worker and orchestrator.

## Impact
On a fresh database, jobs may enqueue but cannot be claimed, recovered, or completed unless functions were installed out of band.

## Recommended solution
Choose an active implementation: reviewed database functions in a forward migration or equivalent transactional repository SQL. Preserve atomic claims, lease ownership, expiry recovery, and owner-checked completion. Never execute archived migrations. Add a fresh-database integration test for enqueue, claim, expiry/recovery, and completion, plus concurrency and least-privilege checks.

## Architecture alignment
Crawl acquisition is a durable execution workflow; active persistence contracts must own job lifecycle and lease guarantees.

## Verification criteria
Fresh migrated database supports full dispatcher lifecycle; concurrent workers cannot claim the same lease; only lease owner can complete.
