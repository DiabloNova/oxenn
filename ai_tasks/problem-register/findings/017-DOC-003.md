# 17 — DOC-003: Route specification declares a superseded roadmap path as its supreme source of truth

## Source
- Finding ID: `DOC-003`
- Original audit: `ai_tasks/docs-folder-audit.md`
- Status: as stated in the source audit; implementation claims remain subject to source verification

## Problem
The sitemap/route specification labels itself authoritative and points contributors to `docs/roadmap/` as the supreme source of truth, but that path is absent. Current documentation governance identifies `docs/Baseline plan/` and `docs/Roadmap/` as authorities, while older roadmap documents under `docs/project/roadmap/` are historical. The migration strategy also points to an obsolete `database/migrations/` location instead of the archived legacy path.

## Evidence
- `docs/architecture/SITEMAP_AND_ROUTE_SPECIFICATION.md` names `docs/roadmap/TASKS.md`, `EXECUTION_ROADMAP.md`, and `PRODUCT_EVOLUTION_ROADMAP.md` as supreme sources.
- `docs/README.md` establishes newer Baseline Plan/Roadmap authorities.
- `docs/project/README.md` marks older roadmap material as historical.
- `docs/architecture/database/migration-strategy.md` uses a stale migration archive path.

## Affected files and paths
- `docs/architecture/SITEMAP_AND_ROUTE_SPECIFICATION.md`
- `docs/README.md`
- `docs/project/README.md`
- `docs/architecture/database/migration-strategy.md`

## Impact
Contributors may follow nonexistent paths or revive historical plans as current authority, producing conflicting product and engineering direction.

## Recommended solution
1. Reconcile the route specification with the current document governance hierarchy.
2. If it remains current, remove the obsolete authority claim and point to the current Baseline Plan and Roadmap; otherwise mark it explicitly historical/superseded.
3. Correct stale migration archive references to the actual legacy archive location.
4. Preserve historical roadmap records and their provenance; do not delete or silently rewrite their historical meaning.
5. Add link/path validation for authoritative documentation and ensure one clear source-of-truth hierarchy is published.

## Architecture alignment
This is governance alignment, not route implementation. Product and engineering scope must be governed by the approved current architecture and Roadmap rather than historical paths.

## Verification criteria
All authority links resolve to current canonical documents; historical sources are labeled; stale migration paths are corrected; no duplicate roadmap authority remains.
