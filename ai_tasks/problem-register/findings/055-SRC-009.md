# 055 — SRC-009: Crawl jobs lack an aggregate byte budget and can follow links to external domains

## Source
- Finding ID: `SRC-009`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: as recorded in the static source audit; runtime/deployment conditions remain subject to revalidation

## Problem
Crawl policy allows high per-job page, response-size, concurrency, and duration ceilings, but the provider enforces only per-response bytes and does not stop when accumulated job bytes exceed a total budget. Extracted HTTP(S) links are queued without same-origin restriction, and caller-supplied policy values are not clamped to subscription limits.

## Evidence
- `policy.ts` allows up to 1,000 pages, 25 MB per response, 16 concurrent requests, and 30 minutes.
- `http-crawl-provider.ts` counts bytes but does not enforce an aggregate job cap.
- `safe-fetcher.ts` enforces per-response, not total, bytes.
- `linksFromHtml` accepts external hosts; crawl route accepts caller policy values without plan clamps.

## Affected files and paths
- Acquisition policy and HTTP crawl provider.
- Safe fetcher and link extraction/queueing.
- Crawl API route and plan/usage enforcement.

## Impact
A job can accumulate large response bodies and crawl unrelated public domains, increasing memory/provider cost and violating the expected site boundary. Caller-supplied values can exceed intended plan constraints.

## Recommended solution
1. Enforce a total per-job byte budget before retaining each response body; also bound pages, requests, concurrency, elapsed time, redirects, and per-response bytes.
2. Default to same-origin crawling and require an explicit allowlist for cross-domain crawling.
3. Revalidate every discovered URL and redirect through the shared DNS-pinned safe-fetch boundary.
4. Clamp all caller-provided policies server-side to plan entitlements and platform hard limits.
5. Reserve usage atomically before work begins and settle actual usage after completion/failure.
6. Cancel outstanding requests when any hard budget is exceeded; record the reason and actual consumption.
7. Add adversarial tests for huge aggregate bodies, cross-domain links, redirect chains, concurrent requests, and plan-limit tampering.

## Architecture alignment
Crawling is a bounded evidence-acquisition workflow. Cost, origin, and data provenance limits must be enforced by the server and cannot be delegated to caller-provided policy values.

## Verification criteria
Total bytes/pages/time/concurrency are enforced; cross-origin fetches require allowlisting; all discovered URLs are safe; plan limits cannot be bypassed; cancellation releases resources.
