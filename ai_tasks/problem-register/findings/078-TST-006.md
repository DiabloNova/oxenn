# 078 — TST-006: Acquisition integration runner can skip successfully and is absent from standard Vitest gates

## Source
- Finding ID: TST-006
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
The acquisition integration runner reads DATABASE_URL and returns after logging a skip if it is absent. It is outside configured Vitest includes and has no dedicated package script; test:acquisition targets only unit tests. The runner contains valuable real PostgreSQL scenarios, but there is no reliable evidence they are invoked.

## Evidence
Evidence: tests/features/acquisition/integration/run-all.ts:22 skips without DATABASE_URL; no package script; Vitest includes omit tests/features.

## Affected files and paths
Integration runner, package.json, CI workflow, disposable PostgreSQL setup.

## Impact
A command may exit without exercising integration scenarios, and standard CI may never run them. A successful skip can be mistaken for a pass.

## Recommended solution
Create a dedicated integration command and CI job with a verified disposable PostgreSQL service. Make missing DB configuration fail when the suite is a required gate; otherwise mark it explicitly skipped and non-green. Emit scenario counts and exact DB target identity. Preserve the existing tenant/concurrency scenarios and add fresh-schema dispatcher tests after SRC-015.

## Architecture alignment
Persistence and tenant boundaries require real adapter integration tests, distinct from mocked unit tests.

## Verification criteria
CI executes the required scenarios against disposable PostgreSQL; zero execution or skipped required suites fail; output records exact commit and test count.
