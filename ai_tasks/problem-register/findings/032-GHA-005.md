# 32 — GHA-005: Vitest emits a Vite config-loader compatibility warning in CI

## Source
- Finding ID: `GHA-005`
- Original audit: `ai_tasks/github-folder-audit.md`
- Status: as recorded in the original folder audit; any conditional claims remain subject to revalidation

## Problem
Unit and UI test jobs emit a warning that the Vite config uses ESM features unsupported by the configured native config loader, with the warning pointing to `vitest.config.ts`. The tests pass at the audited commit, but the toolchain warns that the loading mode may become incompatible with a future major Vite default.

## Evidence
- CI run `42181198077` emitted: `Your Vite config uses features that are unsupported by configLoader: 'native'`.
- The warning points to ESM syntax at `vitest.config.ts:1:1`.
- It appeared in unit and UI test runs.

## Affected files and paths
- `vitest.config.ts`
- Root package/module metadata only if required after impact analysis.

## Impact
Future Vite/Vitest upgrades may break test configuration. A blanket module-mode change could also affect unrelated root scripts and config files.

## Recommended solution
1. Inspect the exact Vite/Vitest version and documented config-loader contract in use.
2. Choose a configuration format/loading mode compatible with the repository's module system.
3. Inventory all root scripts and configuration files before changing package-level `type` or module semantics.
4. Prefer a bounded config-only change when supported; do not suppress the warning or make a broad ESM conversion without a full compatibility review.
5. Run unit, UI, DB, build, lint, and relevant script commands to detect collateral effects.

## Architecture alignment
The test harness is part of the engineering verification layer. Toolchain changes must preserve deterministic discovery and the distinction between pass, fail, and skip.

## Verification criteria
The warning is resolved without broad module regressions; all required test projects and build scripts continue to run.
