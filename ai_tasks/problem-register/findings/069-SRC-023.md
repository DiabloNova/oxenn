# 069 — SRC-023: Default brand identifier is not a UUID although AEO validation requires UUID

## Source
- Finding ID: SRC-023
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
When no brand exists, the action creates an ID like brand-<random>, but the AEO audit schema requires brandId to be a UUID. The dashboard submits the generated ID, so a first-run audit fails validation. Process-local brand storage adds cross-instance unreliability.

## Evidence
Evidence: getBrandsAction creates brand-<random>; audit schema requires UUID; AEO page submits that ID; BrandRepository is process-local (SRC-004).

## Affected files and paths
Brand creation action/repository, AEO audit schema/dashboard, canonical brand schema.

## Impact
First-run AEO audits can fail before execution, and brands created in one process may not exist in another.

## Recommended solution
Generate a UUID and persist the brand through the canonical database-backed repository before exposing it to the UI. Resolve ARCH-003 field mapping first. Verify brand ownership against active organization on every audit request. Remove synthetic IDs from production. Test first-run creation and cross-instance retrieval.

## Architecture alignment
Brand identity is a durable tenant-owned input to Product Intelligence Profile and evidence workflows.

## Verification criteria
Fresh tenant creates persisted UUID brand; audit accepts it; cross-tenant IDs are rejected.

## Related findings
SRC-004, SRC-005, ARCH-003
