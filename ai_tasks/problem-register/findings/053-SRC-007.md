# 053 — SRC-007: AI provider selection silently defaults to mock execution

## Source
- Finding ID: `SRC-007`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: as recorded in the static source audit; runtime/deployment conditions remain subject to revalidation

## Problem
AI visibility provider selection resolves to a mock provider when the caller omits provider type. The normal action path omits it, so audits can run in mock mode even when a Gemini key exists. The LLM client also falls back to MockLLMClient when no key exists without restricting this behavior to development/test. Other advertised model families route to mock rather than live provider adapters.

## Evidence
- `ai-visibility-provider.ts` supports Gemini and Mock; omitted type resolves to Mock.
- `ai-visibility-audit.ts` calls engine without explicit provider.
- `llm-client.ts` returns MockLLMClient when Google key is absent.
- Prompt intelligence routes non-Google providers to Mock.

## Affected files and paths
- AI provider factories/adapters.
- AI visibility audit engine and actions.
- LLM client and prompt intelligence service.
- Model catalog and environment validation.

## Impact
Customer AI workflows can silently store canned mock audits. Missing production credentials can be mistaken for a successful assessment, and model comparison can claim to use providers that are not implemented.

## Recommended solution
1. Define an OXENN-owned provider adapter contract that requires explicit provider/model selection and reports provider readiness.
2. Permit mock fallback only in explicit test/demo mode; production must fail closed when the selected provider is unavailable.
3. Store provider, model, mode, prompt/config version, provenance, cost, latency, and trace IDs with each execution.
4. Expose a model as selectable only after its real adapter and acceptance tests exist.
5. Keep LangChain behind the internal adapter boundary selected for the interim runtime; do not leak framework-specific types into product services.
6. Add tests for missing credentials, provider errors, explicit mock mode, unsupported models, and accurate mode reporting.

## Architecture alignment
The AI runtime is replaceable infrastructure. OXENN owns provider selection, provenance, and business decisions; LangChain is an interim implementation tool, not the owner of product state.

## Verification criteria
Production never silently executes mock; each result reports actual provider/model/mode; unavailable adapters fail clearly; mock tests cannot write LIVE observations.
