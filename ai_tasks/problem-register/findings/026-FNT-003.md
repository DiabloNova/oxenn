# 26 — FNT-003: Three one-byte placeholder files are tracked as font assets

## Source
- Finding ID: `FNT-003`
- Original audit: `ai_tasks/font-folder-audit.md`
- Status: as recorded in the original folder audit; any conditional claims remain subject to revalidation

## Problem
The files `font/1`, `font/Yekan/1`, and `font/tajrid/1` each contain only a single newline byte. They are not font files, manifests, or useful documentation.

## Evidence
- The three paths were inspected and each is one byte.
- No useful font metadata or content exists in them.

## Affected files and paths
- `font/1`
- `font/Yekan/1`
- `font/tajrid/1`

## Impact
The placeholders add noise to the asset tree and can confuse automated inventory, packaging, or future cleanup. Their intended use has not been established.

## Recommended solution
1. Search the repository and workflows for references to these exact paths.
2. Confirm they are not deliberate directory-presence markers required by a script.
3. If no consumer exists, remove them in a separately approved cleanup commit.
4. If placeholders are required, replace them with a clear README/manifest that explains the directory's purpose rather than a one-byte file.
5. Keep any required font license/provenance documents when cleaning the directory.

## Architecture alignment
This is asset hygiene only; it must not change font selection or the application font loader.

## Verification criteria
No runtime or tooling consumer depends on the files, or a documented replacement exists; the final asset inventory contains no opaque one-byte placeholders.
