# 083 — VER-002: Historical RLS verification overstates tenant isolation by classifying five organization-owned tables as global

## Source
- Finding ID: VER-002
- Original audit: ai_tasks/verification-folder-audit.md
- Status: historical evidence or verification gap as described in the original audit; unsafe probes are not authorized for execution

## Original audit claim (historical; superseded)
A historical report claims 51/51 tenant tables and 14/14 global tables covered, but five organization-owned junction tables were excluded from the tenant set and treated as global. Current DB-001 and TST-002 confirm the ownership/policy gap and incorrect test classification.

## Original audit evidence (historical)
Evidence: phase-4/j025 claims full coverage; DB-001 identifies five organization-owned junction tables without RLS; TST-002 lists them as global.

## Affected files and paths
Historical phase-4 RLS report, ownership inventory, current RLS tests and matrix.

## Impact
The historical 51/14 result is not exhaustive tenant-isolation evidence and may mislead reviewers about the current security boundary.

## Recommended solution
Retain the old report as historical evidence but mark its coverage claim superseded/limited. Rebuild the current isolation verification from an independent ownership inventory. Separate tenant-owned tables from global tables and report policy declaration, migration ENABLE/FORCE, and live verification independently. Re-run two-tenant read/write tests only against a verified disposable database after explicit approval.

## Architecture alignment
Organization ownership and Product Evidence Graph relationships must remain within tenant boundaries; missing policies cannot imply global ownership.

## Verification criteria
A current verification report lists all tenant-owned tables independently and tests cross-tenant access; historical coverage is not presented as current.

## Related findings
DB-001, DOC-001, SCR-001, SRC-003, TST-002
