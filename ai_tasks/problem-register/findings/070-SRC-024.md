# 070 — SRC-024: Digital Twin capability described in product scope has no implementation in src/

## Source
- Finding ID: SRC-024
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
The source audit found no Digital Twin domain/service/action, real-versus-target state model, gap calculation, plan lifecycle, execution state, or user–AI execution conversation. Adjacent SEO/AEO assessments do not establish that this capability exists.

## Evidence
Evidence: complete source search found no executable Digital Twin workflow; only a static documentation index hit.

## Affected files and paths
Product architecture/Roadmap, Product Intelligence Profile, assessment, simulation/ROI, planning/execution, continuous improvement.

## Impact
The product may be described as offering a capability that is not implemented; engineering may build a disconnected generic twin subsystem if the domain is not defined first.

## Recommended solution
Confirm scope against approved product architecture and MVP catalog. If retained, define observed state with evidence/freshness, versioned target state, gap metrics/uncertainty, scenarios, human approval, execution records, and outcomes. Map it into existing assessment, simulation/ROI, Planning & Execution, and Continuous Improvement domains. Define the AI dialogue as a controlled interface, not an authority to execute. If deferred, mark planned/not implemented.

## Architecture alignment
Digital Twin must use existing assessment/evidence/planning domains rather than a parallel subsystem.

## Verification criteria
Product decision is recorded; domain/lifecycle specified if retained; docs distinguish target architecture from implemented capability.
