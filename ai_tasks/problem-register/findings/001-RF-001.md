# 001 — RF-001: Repository reconnaissance generator can overwrite its report with incomplete output

## Source
- Finding ID: `RF-001`
- Original audit: `ai_tasks/root-files-audit.md`
- Source location: repository root
- Status in source audit: confirmed static defect

## Problem
The repository reconnaissance generator invokes helper scripts that are not present at the paths it uses, does not stop when those commands fail, and can still move a partially generated temporary file over the existing reconnaissance report. It also depends on the caller's current working directory rather than resolving paths relative to the script itself.

## Evidence
- `update_recon.sh:9` invokes `bash get_routes.sh`.
- `update_recon.sh:25` invokes `bash get_signatures.sh`.
- The referenced root-level helper files were absent during the audit.
- The script does not enable fail-fast behavior or verify required helper exit statuses.
- `update_recon.sh:45` promotes the generated temporary file to `verification/fe/FE-000-recon.md`.

## Affected files and paths
- `update_recon.sh`
- `verification/fe/FE-000-recon.md`
- The intended route/signature generator locations and their inputs, which must be identified before changing the script.

## Impact
A failed reconnaissance run can destroy a previously valid report and replace it with incomplete content while appearing to have completed. Running the script from a different working directory can also make its relative paths resolve incorrectly. This undermines the reliability of repository evidence used by later engineering work.

## Recommended solution
1. Identify the canonical route and signature generation commands from the current repository scripts and package configuration; do not recreate missing helpers based on guessed behavior.
2. Resolve the repository root from the script's own location, then construct all input and output paths from that root.
3. Make each required generation step fail closed: propagate non-zero exit codes and stop before touching the current report.
4. Generate into a unique temporary file in the destination filesystem.
5. Validate that all expected sections and non-empty outputs exist before promotion.
6. Replace the existing report atomically only after every generation and validation step succeeds; clean up temporary files on both success and failure.
7. Add shell-level tests for missing helpers, failed generators, invocation from another working directory, and preservation of the prior report after failure.

This is a tooling/evidence-integrity correction. It must not change the product architecture or introduce a second source of route metadata.

## Architecture alignment
The generator should remain a deterministic repository-maintenance tool. Its output is evidence, not an authority that can silently replace source-of-truth application contracts. Any generated metadata should identify its source revision and generation command.

## Verification criteria
- A missing or failing required generator exits non-zero.
- The existing report remains byte-for-byte unchanged on every failed run.
- Running from the repository root or another working directory produces the same correct result.
- A successful run validates the temporary report before atomic promotion.
- Tests cover failure cleanup and preservation behavior.
