# 33 — GHA-006: Deprecated Node APIs are reported in CI without identifying the owning dependency

## Source
- Finding ID: `GHA-006`
- Original audit: `ai_tasks/github-folder-audit.md`
- Status: as recorded in the original folder audit; any conditional claims remain subject to revalidation

## Problem
CI logs at the audited main commit emitted Node deprecation warnings for `punycode` (DEP0040) and legacy `url.parse()` behavior (DEP0169). The logs do not identify the package or call site responsible. The warning alone does not establish an exploitable vulnerability.

## Evidence
- Build and Test emitted DEP0040 for `punycode`.
- Unit Tests emitted DEP0040 and DEP0169.
- The workflow log did not attribute the warnings to an owner package.

## Affected files and paths
- Dependency graph and package lockfile.
- Code/configuration that loads the package(s), to be identified by diagnostics.

## Impact
Deprecated APIs may become unsupported and legacy URL parsing can have security implications. Without attribution, upgrading arbitrary dependencies or patching package files would be guesswork.

## Recommended solution
1. Reproduce the warning with a scoped diagnostic run that captures warning stacks or otherwise attributes the requiring package.
2. Identify whether the owner is direct, transitive, or application code and record the exact dependency path/version.
3. Check supported upstream releases, compatibility, usage, tests, and rollback requirements before upgrading.
4. If no compatible release exists, evaluate a maintained replacement or a narrowly scoped application-level migration.
5. Do not suppress the warning or edit installed `node_modules` files as a durable fix.
6. Re-run CI and confirm both warning classes are resolved or explicitly accepted with a tracked upstream issue.

## Architecture alignment
Dependency maintenance must be evidence-led. The project should preserve reproducible dependency state and avoid unrelated upgrades during a focused remediation.

## Verification criteria
Each warning is attributed to a concrete package/call site; a compatible fix is tested; no blanket warning suppression is introduced.
