# 29 — GHA-002: GitHub Actions references are mutable tags and no workflow dependency lockfile is present

## Source
- Finding ID: `GHA-002`
- Original audit: `ai_tasks/github-folder-audit.md`
- Status: as recorded in the original folder audit; any conditional claims remain subject to revalidation

## Problem
All external actions in the two audited workflow files are referenced by mutable major-version tags such as `@v4`. The `.github/` tree contains no workflow dependency lockfile. This is a supply-chain configuration risk; no compromise was observed.

## Evidence
- Both workflow files use major-version tags.
- No action dependency lockfile was present in the complete `.github/` tree.
- GitHub secure-use guidance identifies full commit SHAs as immutable references and documents workflow dependency lockfiles.

## Affected files and paths
- Both audited workflow files.
- A repository-root workflow dependency lockfile if adopted.

## Impact
A tag can move or be deleted, so future runs may execute action code different from the code reviewed when the workflow was authored.

## Recommended solution
1. Choose the supported workflow dependency lockfile mechanism if available for this repository; otherwise pin every action to a verified full-length commit SHA.
2. Verify each SHA belongs to the official upstream action repository and review transitive action dependencies where the lockfile supports them.
3. Establish a controlled update process that reviews upstream release notes and diffs before changing pins.
4. Resolve the action versions first (GHA-001), then generate/update the lockfile or SHA references in one coordinated change.
5. Add a CI policy check that rejects unpinned third-party action references.

## Architecture alignment
The CI supply chain must be reproducible and reviewable. Immutable action references complement, but do not replace, the repository's own test and approval controls.

## Verification criteria
All external actions are immutably pinned or locked; the lock data matches the workflow references; updates are reviewable and CI validates pinning.
