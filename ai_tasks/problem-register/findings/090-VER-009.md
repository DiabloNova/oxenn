# 090 — VER-009: Historical API productionization claims require revalidation against current source and architecture

## Source
- Finding ID: VER-009
- Original audit: ai_tasks/verification-folder-audit.md
- Status: historical evidence or verification gap as described in the original audit; unsafe probes are not authorized for execution

## Problem
A historical report describes public API authentication, atomic quota enforcement, rate limiting, and integration tests as productionalized. Current source audit finds quota middleware with no route consumers and a local-only API key UI with no create/revoke actions or middleware route integration. The historical test invocation also targets a legacy path outside standard Vitest projects.

## Evidence
Evidence: phase-6/j036 makes productionization claims; SRC-010 finds no quota consumers; SRC-021 finds no usable key lifecycle; test command uses legacy direct tsx path.

## Affected files and paths
Historical API report, API key settings/service, quota middleware, public API routes, test runner inventory.

## Impact
The old report cannot prove the current public API contract is operational. Branch divergence or later changes may explain the difference; revalidation is required before including it in product scope.

## Recommended solution
Keep the historical report unchanged but mark its claims as point-in-time. Decide whether public API/key lifecycle/quotas are in MVP scope. If retained, verify actual key creation/revocation, hashed storage, route middleware, durable quota enforcement, rate limits, and integration tests on the current branch. Reconcile the docs only after evidence is captured.

## Architecture alignment
Commercial API access is governed by service entitlements, organization authorization, and durable usage metering.

## Verification criteria
Current API capability has a fresh commit-bound verification report; old claims are not used as current proof; out-of-scope features are marked accordingly.
