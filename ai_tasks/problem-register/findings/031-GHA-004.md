# 31 — GHA-004: Regression-baseline workflow is scoped to a stale branch and has no current baseline trigger

## Source
- Finding ID: `GHA-004`
- Original audit: `ai_tasks/github-folder-audit.md`
- Status: as recorded in the original folder audit; any conditional claims remain subject to revalidation

## Problem
The regression-baseline workflow triggers only on pushes to `fix/audit-remediation`, with no manual dispatch, main push, or pull-request trigger. Its latest recorded run was October 19, 2026, on a branch then 256 commits behind main and zero commits ahead. Whether the workflow is archival or intended to be active has not been decided.

## Evidence
- `.github/workflows/capture-regression-baseline.yml:4-6` triggers only on `fix/audit-remediation`.
- No `workflow_dispatch`, `push: main`, or PR trigger was present.
- Latest run `39208665432` was on commit `33234c9372a82ebbb2ac46581fdc913ce4a04dbe` (2026-10-19).
- At audit time the branch was 256 commits behind main.

## Affected files and paths
- `.github/workflows/capture-regression-baseline.yml`
- Audit-governance documentation defining baseline lifecycle.

## Impact
If active, the workflow fails to capture current baselines. If intentionally historical, its current trigger may be correct but is not labeled clearly. The ambiguity can lead to stale evidence being treated as current.

## Recommended solution
1. Decide whether this workflow is a one-time historical capture or an active baseline mechanism.
2. If archival, label it historical, preserve the exact artifact/commit provenance, and avoid implying that it tracks current main.
3. If active, define the authoritative baseline input and a deliberate trigger (manual, protected mainline, or approved release event); avoid triggering destructive or expensive checks on arbitrary pushes.
4. Make the workflow record the exact commit, branch, environment, commands, and artifact retention metadata.
5. Revalidate the workflow against current audit governance before enabling any new trigger.

## Architecture alignment
Verification evidence must be tied to exact code revisions and environments. A stale branch artifact is historical context, not current implementation proof.

## Verification criteria
The workflow has an approved lifecycle, triggers only on the intended source, and every artifact identifies exact commit/environment and is labeled historical or current.
