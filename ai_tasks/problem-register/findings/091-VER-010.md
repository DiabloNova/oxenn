# 091 — VER-010: Old deployment and static-health memos are historical, not current operational guidance

## Source
- Finding ID: VER-010
- Original audit: ai_tasks/verification-folder-audit.md
- Status: historical evidence or verification gap as described in the original audit; unsafe probes are not authorized for execution

## Problem
Historical deployment/static-health memos state that GitHub Actions are absent and record old failing baselines. Current repository contains CI and regression-capture workflows, and later reports describe different commits and gates. These old conclusions remain valid only for their cited revisions.

## Evidence
Evidence: phase-0/deploy-memo says .github/workflows absent; current workflows exist; historical static-health and M5 reports refer to older commits and different gate states.

## Affected files and paths
verification/phase-0 deployment memos, phase-5 gate review, current CI workflow and operational docs.

## Impact
Copying old status into current checklists can cause incorrect operational decisions or imply a failure that has since changed.

## Recommended solution
Preserve old reports as historical. Add prominent baseline metadata and historical labels. Create new operational guidance from current main/target commit, exact workflow run, deployment environment, and verified runtime evidence. Avoid rewriting past conclusions; link them to subsequent reports that supersede current-state interpretation.

## Architecture alignment
Historical technical state is provenance, not current operational truth. Current architecture acceptance requires exact revision/environment evidence.

## Verification criteria
Current runbooks reference current workflows and commit-bound evidence; historical memos are labeled and never presented as live status.
