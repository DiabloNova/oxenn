# 071 — SRC-025: English routes receive Persian-only metadata and font assignments

## Source
- Finding ID: SRC-025
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
The localized layout exports static Persian title/description metadata for every locale and applies Persian font variables to both fa and en routes. Locale state is otherwise handled correctly; the defect is metadata and typography assignment.

## Evidence
Evidence: app/[locale]/layout.tsx has static Persian metadata and font variables; fonts.ts defines Persian setup without English assignment.

## Affected files and paths
Localized root layout, metadata generation, central font loader, global typography and visual tests.

## Impact
English pages can publish Persian search/social metadata and render Latin text using an unintended font stack.

## Recommended solution
Generate metadata per locale including translated title/description/canonical/alternates as required. Assign Persian and Latin font stacks through the central loader and locale-aware layout variables. Coordinate assets with FNT-001/FNT-002. Test lang/dir, headings, navigation, metadata, and both locales.

## Architecture alignment
Localization belongs to the shared frontend shell and central configuration.

## Verification criteria
fa/en routes emit correct metadata, lang/dir, and font families; visual and metadata tests cover both.

FNT-001, FNT-002, DOC-005
