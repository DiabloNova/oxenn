# 081 — TST-009: Test suite does not establish provider mode and provenance behavior end to end

## Source
- Finding ID: TST-009
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
Static scan found no HYBRID references and only sparse LIVE references; the suite is heavily mock-oriented. No end-to-end test verifies LIVE/MOCK/HYBRID contracts, prevents mock-derived values from being represented as measured output, or checks provenance/version compatibility across assessment and evidence persistence.

## Evidence
Evidence: 112-file scan found no HYBRID references and LIVE in four files; MOCK in 67 files; no end-to-end mode/provenance suite identified.

## Affected files and paths
AI provider adapters, assessment pipelines, persistence/evidence graph, contract gates and tests.

## Impact
Isolated unit tests may pass while users receive mock values as live measurements or incompatible provider/model evidence is persisted.

## Recommended solution
Define mode/provenance contract tests at adapter, pipeline, persistence, and API boundaries. Verify LIVE requires real provider evidence; MOCK is explicit and isolated; HYBRID identifies each field's source/mode. Assert model/provider/version, freshness, source, and trace metadata. Prevent mock values from entering production observations and preserve UNKNOWN distinct from ZERO. Use deterministic mocks for unit tests but require real adapter integration gates where promised.

## Architecture alignment
Directly validates provider adapter, Contract & Provenance Gates, versioned evidence, and UNKNOWN != ZERO.

## Verification criteria
End-to-end tests cover all three modes; mock output cannot masquerade as live; provenance is retained across persistence and reporting.
