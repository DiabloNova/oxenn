# 059 — SRC-013: Public free-audit endpoint has no authentication or rate limit

## Source
- Finding ID: `SRC-013`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: Confirmed repository-level authentication and rate-limit gap; the owner-approved access policy requires registered, authenticated users. Runtime/deployment conditions remain unverified.

## Problem
The free-audit route accepts a URL and invokes Firecrawl when configured but does not use session/API-key authorization or a rate limiter. The landing component currently calls a local mock service, so the API route is not the backend for that UI flow. The missing server-side authentication remains a confirmed gap against the owner-approved registered-user policy.

## Owner-approved access policy
All Oxenn services, including free Fred Audit / Free Audit, require a registered account and an authenticated session. Free access is not anonymous access. The policy is recorded in `docs/security/SECURITY_MODEL.md`. This decision resolves the product-policy question; it does not prove that the current route enforces authentication.

## Evidence
- `src/app/api/v1/audit/free/route.ts` accepts a URL and calls Firecrawl.
- No session/API-key authorization or rate limiter is invoked.
- Landing FreeAuditPanel uses local mock service rather than this route.

## Affected files and paths
- Public free-audit API route.
- Safe-fetch boundary, rate limiting, usage metering, and UI service integration.

## Impact
Anyone able to reach the route can repeatedly trigger paid third-party crawling against arbitrary URLs, consuming provider quota. The public route and landing UI also have inconsistent execution behavior.

## Recommended solution
1. Require a registered account and server-validated authenticated session before the endpoint can execute; anonymous access is not permitted.
2. Apply per-user, per-IP, global, and abuse-based rate limits plus strict URL, byte, page, and deadline budgets.
3. Route all URLs through the hardened SSRF-safe fetch service.
4. Reserve/consume a durable free-audit quota before invoking paid providers.
5. Add abuse monitoring and idempotency controls; do not expose provider credentials or detailed internal errors.
6. Connect the landing UI to the real endpoint only after the live workflow is implemented; otherwise label it demo/mock and do not imply provider execution.

## Architecture alignment
Public access must be governed by explicit entitlements and safe-fetch policy. Free does not mean unlimited or unauthenticated access to paid infrastructure.

## Verification criteria
Anonymous and unauthenticated calls are rejected; authenticated free-tier calls are rate-limited and quota-metered; SSRF protection is enforced; the UI accurately states whether the result is mock or live.
