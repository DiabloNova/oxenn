# 097 — ARCH-003: AI-intelligence domain types, repository SQL, and canonical Drizzle schema use incompatible field contracts

## Source
- Finding ID: ARCH-003
- Original source: architecture reconciliation and current architecture-aligned remediation specifications
- Status: additional architecture-driven gap recorded separately from the 94 original audit findings

## Problem
Brand, Page, and DiagnosticFinding domain types/repository SQL use fields that do not match the canonical Drizzle schema or initial migration. Brand expects website/description while schema stores canonical_domain/aliases/industry/target_markets. Page repository uses status_code/indexability/description while schema uses http_status/meta_description/content fields. DiagnosticFinding repository uses website_id/category/code/explanation/affected_resource while schema uses domain/finding_type/severity/confidence/title/description/evidence/recommendation/impact_score/status. Process-local repositories conceal the mismatch.

## Evidence
Evidence: source domain types and SQL in src/features/ai-intelligence/repositories/index.ts conflict with database/schema/index.ts; checked-in initial migration 0000 confirms the same column differences; BrandRepository is process-local; no live database was queried.

## Affected files and paths
AI-intelligence domain types/interfaces, repository SQL/mappers, canonical Drizzle schema, active migrations/snapshots, consumers and tests.

## Impact
Queries may fail or discard fields; in-memory fallback hides incompatibility; IDs and persisted rows can diverge; domain semantics such as indexability and resource identity may be lost if columns are patched without a crosswalk.

## Recommended solution
Do not patch column names individually. Produce an explicit crosswalk for Brand, Website, Page, and DiagnosticFinding across domain types, interfaces, SQL, canonical schema, active migrations/snapshots, and consumers. Decide the business meaning of each field; choose either reviewed schema evolution or revised domain contracts. Define typed bidirectional row mappers for timestamps/nullability/JSONB/arrays/enums/numbers; preserve tenant predicates and soft deletes. Make PostgreSQL the production source of truth and in-memory repositories explicit test/demo adapters only. Ensure upsert returns the actual persisted row/ID. Only after the crosswalk is approved, fix SRC-004 to return mapped result rows.

## Architecture alignment
Canonical schema, domain model, and repository adapter must implement one versioned persistence contract. Product Intelligence Profile and Product Evidence Graph require durable, tenant-scoped evidence.

## Verification criteria
Domain/interfaces/SQL/schema/migrations/snapshots agree; real rows map both directions; process-restart read-after-write works; upsert IDs match persisted rows; tenant isolation and fresh/populated migration tests pass.
