## Original problem
The original audit found four inconsistent descriptions: a 12-table list in the tenant-context specification; an older 51/19 split in the August 2024 reconciliation report; stale 51-table claims in active security/architecture documentation; and an illustrative policy using `app.current_organization_id` instead of `app.current_tenant_id`. It also incorrectly grouped missing-policy junction tables as Global.

## Repository evidence at the original revalidation baseline (historical)
At the original revalidation baseline (`main@4e54e8b`), the generated Reference Matrix recorded 70 tables as 56 Tenant-Owned and 14 Global. Those values are retained as a point-in-time record only; the classification was superseded by PR #130 and is not the current inventory. The original baseline reported declared SELECT/INSERT/UPDATE/DELETE tenant-policy coverage and ENABLE/FORCE coverage in the checked-in migration journal for the then-classified Tenant-Owned set. The five formerly affected junction tables were addressed by migrations `0014_db_001_join_table_rls.sql` and `0015_db_001_composite_tenant_fks.sql`.

The static Matrix deliberately does not claim runtime enforcement. The CI isolation suite has exercised the repository's tenant policies against disposable PostgreSQL; this does not establish production or staging database state. No production database connection or query was made for this finding.

- `docs/security/README.md` and `docs/architecture/README.md` still used stale 51-table claims.

- The documentation folder audit repeated an inaccurate claim that MVP Phase 0 still used 51.
