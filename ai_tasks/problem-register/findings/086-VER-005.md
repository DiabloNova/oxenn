# 086 — VER-005: Legacy system-context probe is unsafe as a general verification runner

## Source
- Finding ID: VER-005
- Original audit: ai_tasks/verification-folder-audit.md
- Status: historical evidence or verification gap as described in the original audit; unsafe probes are not authorized for execution

## Problem
The historical probe falls back to a local postgres superuser URL when DATABASE_URL is absent, prints the full database URL, uses a hardcoded probe account, performs registration/workspace/invitation/member mutations, has no cleanup/rollback for application-level changes, and logs top-level errors without explicitly setting a non-zero exit code.

## Evidence
Evidence: phase-0/probe-system-context.ts:27 fallback URL; :30 prints DATABASE_URL; :64-72 hardcoded account; :120-153 mutating actions; no cleanup; :157 catch only logs.

## Affected files and paths
verification/phase-0/probe-system-context.ts and any scripts or docs that reference it.

## Impact
If run with a non-test database, it can mutate persistent identity/workspace state and leak credentials in logs. It may also exit successfully after failure.

## Recommended solution
Do not run or reuse this script as a current verification runner. Mark it HISTORICAL_ONLY / DO NOT RUN. If a replacement is required, build a new isolated test harness with explicit disposable database identity verification, secret redaction, generated test identities, rollback/cleanup, no production credentials, and non-zero failure exit. Keep the historical artifact unchanged for provenance.

## Architecture alignment
Verification must use isolated infrastructure, explicit environment identity, synthetic fixtures, cleanup, and trustworthy failure semantics.

## Verification criteria
No execution of this historical probe; any replacement refuses non-disposable/ambiguous targets, never prints secrets, cleans all test state, and fails non-zero on error.
