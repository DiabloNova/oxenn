# 066 — SRC-020: Prompt execution returns stale running state after recording failure and applies generic brand aliases

## Source
- Finding ID: SRC-020
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
When provider execution fails, the catch path persists a failed transition but ignores the returned updated object and returns the earlier running object. The service also applies fixed Rasha aliases to every brand, potentially attributing mentions to unrelated customers.

## Evidence
Evidence: prompt-intelligence-service.ts transitions to failed but returns stale object; position analysis uses fixed Rasha aliases globally.

## Affected files and paths
Prompt intelligence service/execution repository, brand profile and alias data.

## Impact
The UI may show a failed run as running; generic aliases can inflate or misattribute customer visibility.

## Recommended solution
Return the updated failed execution. Store verified tenant/brand-specific aliases with provenance and customer review. Reject unknown model identifiers rather than substituting a default. Test provider failure state, alias isolation, and unsupported model IDs.

## Architecture alignment
Execution state must match durable state; brand identity is tenant-owned evidence, not a global demo fixture.

## Verification criteria
Failure response matches persisted state; aliases are brand-specific and verified; unknown model IDs fail clearly.
