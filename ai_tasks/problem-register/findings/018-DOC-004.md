# 18 — DOC-004: Crawl acquisition documentation claims functions absent from the active migration chain

## Source
- Finding ID: `DOC-004`
- Original audit: `ai_tasks/docs-folder-audit.md`
- Status: as stated in the source audit; implementation claims remain subject to source verification

## Problem
The Crawl Acquisition feature architecture describes dispatcher claiming and expired-lease recovery as narrow PostgreSQL SECURITY DEFINER functions. Those functions exist in a quarantined historical migration, but are absent from the active Drizzle migration chain. The documentation therefore claims a database implementation that the active schema does not contain. Application code may have replaced the functions with equivalent transactions, but that has not yet been established by this documentation audit.

## Evidence
- `docs/architecture/features/CRAWL_ACQUISITION.md` describes the claim/recovery functions.
- `database/archive/migrations-legacy/0004_crawl_acquisition.sql` contains the historical functions.
- Active migrations `database/drizzle/0000`–`0013` contain no corresponding definitions.
- The archive README says historical migrations must not be executed.

## Affected files and paths
- `docs/architecture/features/CRAWL_ACQUISITION.md`
- `database/archive/migrations-legacy/README.md`
- `database/archive/migrations-legacy/0004_crawl_acquisition.sql`
- Active dispatcher and worker call sites.

## Impact
Engineers may assume concurrency and lease guarantees exist in the active database when they may only exist in historical SQL or may be absent entirely. Reintroducing archived SQL without review could also restore an obsolete security boundary.

## Recommended solution
1. Trace the actual dispatcher, worker, repository, and transaction call sites before editing the architecture document.
2. Compare the active implementation with the historical invariants: atomic claim, lease recovery, owner-checked completion, and safe concurrency.
3. If application transactions implement the behavior, document the real source path and its guarantees; state that historical functions were replaced, not absorbed into the active schema.
4. If behavior is missing, record the missing contract and design a current implementation behind the repository/worker boundary with explicit transaction and least-privilege semantics.
5. Keep archived migrations immutable and never execute them as a shortcut.
6. Add concurrency, stale-lease, recovery, and duplicate-completion tests against the active implementation.

## Architecture alignment
Crawl acquisition is a durable execution workflow. Job state and lease ownership must be enforced by the active persistence/worker contract, not by an archive or undocumented process-local behavior.

## Verification criteria
Documentation matches the verified active implementation; all lease guarantees have executable tests; archived SQL remains historical and unused.
