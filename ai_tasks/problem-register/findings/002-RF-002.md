# 002 — RF-002: AEO visual verification can terminate unrelated processes and report false success

## Source
- Finding ID: `RF-002`
- Original audit: `ai_tasks/root-files-audit.md`
- Status in source audit: confirmed static defects; runtime impact was not executed

## Problem
The AEO visual verification script kills every process listening on port 3000 without proving that it started that process. It starts the application and waits a fixed five seconds instead of checking readiness, embeds test credentials, writes to a machine-specific absolute path, catches failures without returning a failing exit code, and does not assert that the authenticated target page actually loaded before reporting screenshot success.

## Evidence
- `verify_aeo_content.py:14` kills all PIDs returned by `lsof -t -i :3000`.
- `verify_aeo_content.py:18-25` starts `pnpm start` and sleeps for five seconds.
- `verify_aeo_content.py:42-43` embeds `test@example.com` / `password`.
- `verify_aeo_content.py:59` uses `/home/jules/verification/aeo_content_intelligence.png`.
- `verify_aeo_content.py:65-66` catches exceptions and only prints an error.
- `verify_aeo_content.py:69` force-kills the spawned process group.
- The script does not assert authentication, the expected route, or expected page content.

## Affected files and paths
- `verify_aeo_content.py`
- The app startup and login flow used by the script.
- The test-account fixture/provisioning mechanism.
- The output artifact location and verification invocation.

## Impact
The script can terminate an unrelated developer process, fail to detect a server that never became ready, or produce a green process exit after login/navigation/assertion failure. Its screenshot output is therefore not trustworthy evidence of a working AEO experience.

## Recommended solution
1. Run the application on an isolated, dynamically allocated or explicitly reserved test port owned by the verification process.
2. Track the exact child process/PID or process group created by the script; never kill arbitrary listeners discovered by port number.
3. Replace the fixed sleep with bounded readiness polling against a health or expected-route check.
4. Obtain credentials from a dedicated test fixture or protected environment variables; reject missing/default credentials and do not commit real credentials.
5. Assert successful authentication, the exact localized route, and stable AEO page content before capturing a screenshot.
6. Use a repository-relative or caller-supplied output directory and create it safely.
7. Propagate exceptions and failed assertions as a non-zero process exit status.
8. Use structured cleanup that terminates only the child process created by the test, with a bounded graceful-shutdown period before forced termination.
9. Add tests for server startup failure, authentication failure, missing expected content, output-path portability, and cleanup ownership.

## Architecture alignment
This script is a verification tool, not a product runtime component. It must verify the actual frontend against its real application contract and must not infer backend readiness from a screenshot or from a mocked response.

## Verification criteria
- No process not created by the script is terminated.
- The script does not proceed until the target server is ready.
- Missing credentials or failed authentication cause a non-zero exit.
- The expected page assertions pass before the screenshot is reported as successful.
- The output path works in CI and local environments.
- Cleanup only affects the process tree owned by this run.
