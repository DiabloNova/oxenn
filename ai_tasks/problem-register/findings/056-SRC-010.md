# 056 — SRC-010: Subscription quotas are declared but not consumed by main runtime paths

## Source
- Finding ID: `SRC-010`
- Original audit: `ai_tasks/src-folder-audit.md`
- Status: as recorded in the static source audit; runtime/deployment conditions remain subject to revalidation

## Problem
Plan definitions declare daily crawl, observation, token, brand, and prompt limits, and quota service methods exist, but no call sites consume credits or increment usage counters. The crawl and premium audit routes do not enforce all declared budgets. BudgetService is process-local and its checkAndReserve method does not create a durable reservation.

## Evidence
- `plans.ts` defines quotas such as maxCrawlJobsPerDay, maxObservationsPerMonth, monthlyTokenLimit, maxBrands, and maxPrompts.
- SubscriptionService exposes quota/consume methods without runtime call sites.
- BudgetService is process-local and reservation is not persisted.
- Public API quota middleware has no route consumers (SRC-021).

## Affected files and paths
- Billing plan definitions and SubscriptionService.
- BudgetService and usage counters.
- Crawl, AI, observation, brand, prompt, and public API operation boundaries.

## Impact
Declared plan limits may not be enforced, exposing the service to unmetered provider costs and making customer entitlements misleading.

## Recommended solution
1. Define durable usage dimensions and authoritative counters for each billable operation.
2. Reserve quota atomically before external work; prevent concurrent requests from exceeding limits.
3. Settle actual usage and release unused reservations on success, failure, cancellation, and timeout.
4. Keep quota state in durable storage, not process-local maps.
5. Enforce the same entitlement contract across crawl, AI, observations, brands, prompts, and public API operations.
6. Distinguish hard limits from soft warnings and disclose unavailable/unknown usage state.
7. Add concurrency, rollover, plan-change, retry/idempotency, and failure rollback tests.

## Architecture alignment
Commercial entitlements and usage metering are cross-cutting platform capabilities. They must be durable, atomic, and independent of the AI framework or request process.

## Verification criteria
Each declared quota is either enforced at the operation boundary or explicitly labeled non-enforced; concurrent requests cannot exceed limits; usage survives restarts.
