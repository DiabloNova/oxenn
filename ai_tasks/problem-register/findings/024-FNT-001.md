# 24 — FNT-001: Root font catalogue is not connected to the active central font loader

## Source
- Finding ID: `FNT-001`
- Original audit: `ai_tasks/font-folder-audit.md`
- Status: as recorded in the original folder audit; any conditional claims remain subject to revalidation

## Problem
The root `font/` folder contains 63 font files (~2.60 MiB), but the current application loader imports fonts from `public/fonts/`. The root Yekan collection is a separate WOFF set, Tajrid and BoxFace are not configured, and the repository has no clear ownership/usage contract connecting the root catalogue to the shipped assets.

## Evidence
- The font audit inventoried 66 tracked entries; 63 root font assets were not byte-identical to the 10 files under `public/fonts/`.
- `src/config/fonts.ts` loads from `public/fonts/`; the root catalogue is not the active loader source.
- Source-reference search was incomplete, so absence of every dynamic reference is not claimed.

## Affected files and paths
- `font/**`
- `public/fonts/**`
- `src/config/fonts.ts`
- `globals.css`
- The separate source repository named by the project owner as `oxenn_doxuments`.

## Impact
Two parallel font collections make it unclear which files are approved, maintained, licensed, or actually served. Removing or activating assets without a complete reference and license check could break typography or create distribution risk.

## Recommended solution
1. Verify the exact identity and contents of the designated font-source repository; do not assume the root `font/` folder is the approved source.
2. Create an inventory manifest for each selected family/weight: source, license, commercial/web-embedding permission, locale/glyph coverage, consumer, and shipped status.
3. Select only required variants; validate Persian and Latin glyph coverage and rendered appearance.
4. Use the existing standard served location `public/fonts/` unless architecture review identifies a better single canonical location.
5. Update the central loader and typography tokens only after the source files and licenses are verified.
6. Remove or archive unused duplicate collections only in a separately approved cleanup after repository-wide reference checks; preserve license/provenance evidence.

## Architecture alignment
Typography is a shared design-system asset. One canonical loader and an auditable asset manifest should serve both locales; asset existence is not evidence of browser availability or license permission.

## Verification criteria
Every shipped font has a verified source/license, a central loader reference, required glyph coverage, and rendering tests; unused assets have a documented disposition.
