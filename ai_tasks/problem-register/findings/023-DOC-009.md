# 23 — DOC-009: API documentation includes a source filename in the HTTP endpoint path

## Source
- Finding ID: `DOC-009`
- Original audit: `ai_tasks/docs-folder-audit.md`
- Status: as stated in the source audit; implementation claims remain subject to source verification

## Problem
The API README lists the LLM Analytics endpoint as `/api/v1/analytics/llm/route.ts`. The `route.ts` suffix is a Next.js filesystem implementation filename, not normally part of the public HTTP request path. The actual route must be verified against the current source tree before documenting the public endpoint.

## Evidence
- `docs/api/README.md` lists `/api/v1/analytics/llm/route.ts`.
- The same README labels the APIs implemented and verified; those claims are subject to the broader DOC-005 evidence requirement.

## Affected files and paths
- `docs/api/README.md`
- The corresponding Next.js route file and route tests.

## Impact
API consumers may call a nonexistent URL or misunderstand the difference between public HTTP contract and source-file location.

## Recommended solution
1. Inspect the current route tree and confirm the actual HTTP method, path, authentication, request schema, response schema, and error contract.
2. Document the public URL without the filesystem suffix and list the source file in a separate implementation-reference field.
3. Add an API documentation check that compares documented paths with the route inventory where practical.
4. Revalidate any claim that the endpoint is functional against route tests and its real dependencies; do not infer readiness from a source file's existence.

## Architecture alignment
The API route is an application-layer contract. Its public path and behavior must be explicit and must not expose implementation filenames as part of the external interface.

## Verification criteria
The documented HTTP path matches the actual route; method and contract are verified; source path is listed separately; status claims have evidence.
