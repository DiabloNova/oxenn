# 096 — ARCH-002: Current AI runtime does not implement the approved LangChain interim adapter boundary

## Source
- Finding ID: ARCH-002
- Original source: architecture reconciliation and current architecture-aligned remediation specifications
- Status: additional architecture-driven gap recorded separately from the 94 original audit findings

## Problem
The audited package manifest/lockfile used Vercel AI SDK and @ai-sdk/google; LangChain was absent. The approved direction is to use LangChain as an interim implementation framework until SCRS is operational. This is a target-architecture gap, not proof that absence of LangChain alone is a current runtime defect. Existing direct provider paths and mock fallbacks make a stable OXENN-owned boundary necessary first.

## Evidence
Evidence: audited package.json/lockfile included Vercel AI SDK and @ai-sdk/google, not LangChain; SRC-007/SRC-008 record direct provider and mock fallback behavior.

## Affected files and paths
AI Intelligence Pipeline, provider/model selection, runtime adapter, workflow orchestration, telemetry/evaluation, contract/provenance gates.

## Impact
Adding LangChain directly to feature modules would create framework coupling without solving ownership of business state, permissions, quotas, approvals, or provenance.

## Recommended solution
Define a stable OXENN-owned runtime interface first, including task/contract identity, workspace scope, provider/model, mode, trace IDs, typed failures, usage/cost metadata. Implement LangChain behind that adapter; do not expose its types outside the adapter. Keep workflow state, retries, permissions, approvals, quotas, business rules, and execution in OXENN. Make LIVE/MOCK/HYBRID explicit; production must fail closed if provider unavailable. Migrate workflows incrementally after inventory. Evaluate LangGraph only for a demonstrated multi-step need. Treat SCRS as a later replacement candidate only after operational readiness and real OXENN workload comparisons. Verify current LangChain APIs/version using official docs when implementation begins.

## Architecture alignment
The AI runtime is replaceable infrastructure. OXENN owns provider selection, evidence provenance, business decisions, durable state, and approvals; LangChain is an interim adapter implementation only.

## Verification criteria
All model calls use OXENN-owned interface; no domain module imports LangChain types; modes and provenance are explicit; LLM output cannot bypass gates/approvals; SCRS is not activated before workload evaluation.
