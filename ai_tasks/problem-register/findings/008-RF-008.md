# 008 — RF-008: Agent operating contract contains duplicate and inconsistently formatted section numbers

## Source
- Finding ID: `RF-008`
- Original audit: `ai_tasks/root-files-audit.md`
- Status in source audit: confirmed document-structure defect

## Problem
The root `AGENTS.md` contains duplicate section numbering and inconsistent heading formatting. One section numbered 15 appears early in the document and another section numbered 15 appears much later after sections 44 and 45. Another heading uses `16.Mandatory` without a space.

## Evidence
- `AGENTS.md:511` is titled `## 15. Generated Artifacts`.
- `AGENTS.md:1252` is titled `## 15. Authorization and super_admin Policies`.
- `AGENTS.md:534` uses `## 16.Mandatory Task Report Rule`.

## Affected files and paths
- `AGENTS.md`

## Impact
Duplicate numbering makes references to operating rules ambiguous and makes the appended authorization policy harder to locate. The formatting defect does not by itself establish a runtime authorization failure.

## Recommended solution
1. Review the full heading hierarchy and determine the intended placement of the appended authorization policy.
2. Renumber headings consistently in document order, preserving the meaning and scope of every rule.
3. Normalize punctuation and spacing in numbered headings.
4. Check internal links, anchors, and any external references that cite section numbers.
5. Add a lightweight documentation check for duplicate numbered headings and malformed number/heading separators.

## Architecture alignment
Operating instructions are governance material, not an implementation substitute. The edit must preserve existing security requirements and must not weaken or reinterpret authorization rules while correcting numbering.

## Verification criteria
- Numbered headings are unique and sequential within their intended hierarchy.
- Internal links and section references resolve.
- No policy text is deleted, weakened, or semantically changed.
- The documentation check catches duplicate numbering.

## Related findings
None identified in the root audit. This is an isolated documentation-maintenance issue.
