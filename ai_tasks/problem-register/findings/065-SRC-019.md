# 065 — SRC-019: Prompt scheduling and scheduled monitoring persist configuration but do not execute work

## Source
- Finding ID: SRC-019
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
Prompt schedules are saved but no module reads due schedules or dispatches executions. The hourly scheduledMonitoring function only logs and returns success without loading configs, crawling sites, creating snapshots, or alerts. A generic in-memory queue drops items after a timeout without executing them.

## Evidence
Evidence: PromptIntelligenceService.schedulePrompt persists cron metadata; no due-schedule dispatcher found; Inngest function only logs; InMemoryJobQueue drops queued items and has no runtime consumers.

## Affected files and paths
Prompt scheduling service, Inngest scheduledMonitoring, in-memory queue, user-facing schedule controls.

## Impact
Users may believe scheduled prompts and monitoring are active when only configuration is stored. Cron can report success without performing monitoring.

## Recommended solution
Decide whether scheduling is MVP scope. If approved, implement durable schedule state, dispatcher, idempotent job creation, worker execution, retries, and observable results. Persist snapshots/alerts with provenance. If deferred, hide or clearly mark controls unavailable and prevent them from implying active automation. Test due dispatch, missed-run recovery, duplicate prevention, failures, and evidence creation.

## Architecture alignment
Scheduled work belongs to Planning & Execution and Continuous Improvement and must be durable and observable.

## Verification criteria
Every advertised schedule performs real work with durable evidence or is clearly unavailable; successful cron runs correspond to actual jobs.
