# 036 — PUB-003: Icon assets are inconsistently wired into app metadata and the SVG color-scheme mapping is inverted

## Source
- Finding ID: `PUB-003`
- Original audit: `ai_tasks/public-folder-audit.md`
- Status: as recorded in the original public-folder audit; incomplete source-search limitations are preserved

## Problem
The app-directory favicon.ico exists and contains standard resolutions, but Apple/icon PNG variants under public/ are not declared in the inspected localized metadata and there is no corresponding app-directory convention file. The root public/icon.svg maps a dark square to light preference and a light square to dark preference.

## Evidence
- Localized metadata has no icons declaration.
- `public/apple-icon.png`, `public/icon-dark-32x32.png`, and `public/icon-light-32x32.png` exist under public/.
- `public/icon.svg` assigns the dark variant to light preference and vice versa.
- `app/favicon.ico` contains 16, 32, 48, and 256 pixel images.

## Affected files and paths
- `src/app/[locale]/layout.tsx` metadata.
- `public/icon.svg` and PNG icon assets.
- App-directory icon convention files.

## Impact
Browsers and devices may choose inconsistent icons or use an icon with insufficient contrast for the active color scheme. Duplicate assets can also create uncertainty about the canonical brand mark.

## Recommended solution
1. Select one canonical favicon, Apple touch icon, and light/dark icon strategy consistent with the current brand identity.
2. Wire assets through Next.js metadata conventions or explicit metadata declarations, not through undocumented duplicate paths.
3. Correct the SVG media/color-scheme mapping and verify the actual rendered colors in both schemes.
4. Validate dimensions, file formats, accessibility/brand contrast, and localized metadata behavior.
5. Remove redundant variants only after checking every explicit URL reference and browser convention.

## Architecture alignment
Brand metadata is part of the shared frontend shell. Icon choice must be consistent with the approved brand assets and theme behavior.

## Verification criteria
The browser resolves the intended canonical icons; dark/light variants are not inverted; metadata tests cover both locales and theme variants.
