# 068 — SRC-022: Invoice page reports payment success without processing or verifying payment

## Source
- Finding ID: SRC-022
- Original audit: ai_tasks/src-folder-audit.md
- Status: as recorded in the static source audit; runtime/provider/database conditions remain subject to revalidation

## Problem
The invoice page contains static payment details and a handler that waits locally before changing client state to success. It does not call a payment gateway, verify a bank/crypto transaction, create a server payment record, or reconcile subscription state.

## Evidence
Evidence: invoice page handler is a local timer/state update; no provider verification or durable payment record exists in the inspected path.

## Affected files and paths
Invoice page, payment/billing domain, subscription state and any future approved provider/webhook adapter.

## Impact
A user can be shown payment success without payment being received or verified; client state could appear to activate paid service.

## Recommended solution
Until provider and verification design are approved, disable payment collection/success and show only a clearly non-payable preview. If later approved, use server-side provider/webhook verification, signature checks, idempotency, and immutable transaction records. Activate entitlements only after verified settlement. Treat client callbacks/references as untrusted. Test forged success, duplicate webhooks, failed settlement, refunds, and customer mismatch.

## Architecture alignment
Paid entitlements must derive from verified server-side payment evidence, never client state.

## Verification criteria
No client-only path produces paid status; verified settlement is required; webhook processing is idempotent.

## Related findings
ARCH-001, SRC-010
