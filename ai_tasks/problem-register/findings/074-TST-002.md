# 074 — TST-002: Tenant-owned junction tables are explicitly excluded from isolation tests as global

## Source
- Finding ID: TST-002
- Original audit: ai_tasks/tests-folder-audit.md
- Status: confirmed test-coverage or contract gap as recorded in the tests audit

## Problem
The isolation suite places pages_keywords, pages_topics, pages_entities, keywords_topics, and topics_entities in GLOBAL_TABLES, describes them as global, and checks they are readable without tenant context. Database audit DB-001 confirms these are organization-owned tables lacking RLS.

## Evidence
Evidence: tests/isolation/suite.ts:8-23 lists the five as global; :525-538 asserts unscoped readability; DB-001 establishes organization ownership.

## Affected files and paths
tests/isolation/suite.ts, canonical table ownership inventory, RLS migration/tests.

## Impact
The isolation suite encodes the same incorrect classification as the underlying RLS defect and cannot detect cross-tenant access to these tables.

## Recommended solution
Remove the five tables from GLOBAL_TABLES and classify them from an independent ownership contract. Add two-organization SELECT/INSERT/UPDATE/DELETE isolation tests and verify missing tenant context is rejected. Keep explicit global tables separate from tenant-owned tables whose RLS is missing. Coordinate with DB-001 and SCR-001.

## Architecture alignment
Tenant ownership is a domain/data property; association rows in the evidence graph inherit the owning organization's boundary.

## Verification criteria
The five tables are tested as tenant-owned; unscoped access fails; cross-tenant reads/writes fail; the suite no longer treats missing RLS as global.
