# 039 — PUB-006: Platform taxonomy lists Anthropic and Anthropic Claude as peer monitored destinations

## Source
- Finding ID: `PUB-006`
- Original audit: `ai_tasks/public-folder-audit.md`
- Status: as recorded in the original public-folder audit; incomplete source-search limitations are preserved

## Problem
PlatformsSection contains both “Anthropic Claude” (`claude`) and “Anthropic” (`anthropic`) as separate entries in one list of AI engines. This mixes a product/model with its vendor, making it unclear whether the taxonomy represents providers or model destinations.

## Evidence
- The current PlatformsSection array contains both labels/slugs.
- Both appear in the same list of monitored AI engines.

## Affected files and paths
- PlatformsSection provider/model data array.
- Provider logo taxonomy and any analytics/report labels that consume it.

## Impact
Users may misunderstand the set of engines being measured, and downstream counts may treat a vendor and its model as separate destinations without a defined rule.

## Recommended solution
1. Decide whether the list represents model/engine destinations or provider organizations.
2. If it represents engines, use a consistent model-level taxonomy and map each model to its vendor separately.
3. If it represents providers, list Anthropic once and represent Claude as a product/model attribute rather than a peer provider.
4. Define stable IDs, display labels, provider ownership, and aggregation rules in one typed catalog consumed by UI and analytics.
5. Update logos and tests so a provider and model are not double-counted unless that is an explicit product requirement.

## Architecture alignment
Provider/model identity must be consistent across Product Evidence Graph, integrations, and reporting. The presentation taxonomy must not distort the underlying measured entity.

## Verification criteria
The catalog has one explicit taxonomy level; vendor/model relationships are represented structurally; reports and UI do not double-count entities.
