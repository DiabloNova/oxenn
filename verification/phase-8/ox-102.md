## Anomalies & Pre-Existing Failures (DO NOT FIX IN OX-102)

During the migration, tests were strictly ported 1:1 using `vitest` `describe/it` wrappers without touching the body. Four files have failing suites that were **pre-existing** before migration. These failures exist because the tests run without `DATABASE_URL` during unit testing, but the actual module code or test fixture depends on `PostgresClient` via `TenantContextManager.runWithTenantContext` or `createSession`, causing a crash `Error: DATABASE_URL is required`.

1. **`tests/unit/services/audit-engine/site-architecture.test.ts`**
   - **Pre-existing Failure:** Running the legacy file directly via `pnpm tsx` crashes with:
     ```
     ❌ Test Suite failed: Error: DATABASE_URL is required
        at new PostgresClient (/app/src/features/admin/infrastructure/persistence/postgres/index.ts:48:13)
        at Function.getInstance (/app/src/features/admin/infrastructure/persistence/postgres/index.ts:68:33)
        at Function.runWithTenantContext (/app/src/core/database/tenant-context/index.ts:303:37)
     ```
   - **Reason:** The original test runs `TenantContextManager.runWithTenantContext` and requires a DB.

2. **`tests/unit/services/audit-engine/technical-seo-analyzer.test.ts`**
   - **Pre-existing Failure:** Running the legacy file directly via `pnpm tsx` crashes with:
     ```
     ❌ Test Suite failed: Error: DATABASE_URL is required
        at new PostgresClient (/app/src/features/admin/infrastructure/persistence/postgres/index.ts:48:13)
     ```
   - **Reason:** The original test runs `TenantContextManager.runWithTenantContext` directly calling `PostgresClient.getInstance()`.

3. **`tests/unit/services/cache/cache.test.ts`**
   - **Pre-existing Failure:** Running the legacy file directly crashes with:
     ```
     [SystemContext] Leasing client for purpose: sys-login
     ❌ Test Suite Failed with Error: Error: DATABASE_URL is required
        at new PostgresClient (/app/src/features/admin/infrastructure/persistence/postgres/index.ts:48:13)
     ```
   - **Reason:** Uses `await createSession({ ... })` requiring `TenantContextManager.runWithSystemContext` under the hood.

4. **`tests/unit/services/jobs/jobs.test.ts`**
   - **Pre-existing Failure:** Running the legacy file directly crashes with the same error:
     ```
     [SystemContext] Leasing client for purpose: sys-login
     ❌ Test Suite Failed with Error: Error: DATABASE_URL is required
     ```
   - **Reason:** This file also uses `await createSession(mockUser);` which fails because it initializes a real DB client internally.

In accordance with OX-102 instructions ("do not fix product bugs discovered by tests", "do not redesign or strengthen the mocks", "Assertion semantics preserved 1:1"), these tests were ported exactly as they were without adding new vitest mock behaviors that weren't present in the original test. Also, all `run*` execution functions were actually invoked within the `it()` blocks to properly ensure assertions ran.

*(Note: During migration, relative path imports were corrected to use `@/` where applicable, and TypeScript type-checking issues resulting from incorrect imports from `src/features/` vs `src/lib/` or `src/services/` were fixed to refer to the actual source file locations. `/* eslint-disable ... */` was added to migrated vitest specs to pass strict linting).*
