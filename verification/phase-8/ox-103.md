## 3. Exceptions & Unmigrated Files (DB/Orchestrators)

The following files were originally classified as `unit` in MP-04 but failed strict isolation rules during execution (they required `pg`, `Pool`, or `DATABASE_URL` connections, resulting in explicit failure logs). They have been left in place and properly classified as `db` for OX-104:

- `tests/features/public-api/public-api.test.ts`: Requires `MIGRATION_DATABASE_URL` and instantiates `Pool`.
- `tests/scripts/database/db-push-guard.test.ts`: Requires `DATABASE_URL` to test catalogue failure logic.
- `tests/features/ai-intelligence/application.test.ts`: Requires DB for `PostgresClient` instantiated inside CQRS handlers.
- `tests/features/ai-intelligence/vector-store.test.ts`: Requires DB via `VectorStoreService` instantiating `PostgresClient`.
- `tests/features/analysis/competitive.test.ts`: Triggers an API route `POST` that establishes a DB connection and fails with 500 without `DATABASE_URL`.
- `tests/features/analytics/llm-analytics.test.ts`: Hits route relying on DB auth context wrapper.
- `tests/features/audit/premium-audit.test.ts`: Deep service calls invoke DB.
- `tests/features/content/studio.test.ts`: Content Studio handlers use PG.
- `tests/features/optimization/technical.test.ts`: Triggers internal functions throwing `DATABASE_URL is required`.
- `tests/features/ai-intelligence/services/competitor-discovery-service.test.ts`: Execution throws due to dynamic loading of DB classes inside its broader context.
- All `run-all.ts` files were left intact as orchestrators, per instructions.
