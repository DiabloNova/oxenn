# OX-104: DB test execution surface

## Moved Spec List

The following files imported `vitest` and were classified as `db` (verified through reading the files and cross-referencing against `verification/phase-7/j038.md`), so they were moved to `tests/db`:

* `tests/db/actions/empty-states.test.ts`
* `tests/db/core/tenant-context/system-mode-bypass.test.ts`
* `tests/db/services/auth/error-mapping.action.test.ts`
* `tests/db/services/auth/error-mapping.test.ts`

These were the only specs that met the criteria. Other db-classified scripts continue to exist but were skipped in this phase as they use `assert` natively (not vitest).

## Fail-closed Demonstration Output

The legacy acquisition runner skip logic was fixed to fail-closed during CI environments:

```
$ CI=true npx tsx tests/features/acquisition/integration/run-all.ts
❌ acquisition integration suite failed: DATABASE_URL is not set in CI environment
```

When run locally with `CI=false`, it gracefully skips:

```
$ CI=false npx tsx tests/features/acquisition/integration/run-all.ts
⚠️ acquisition integration suite skipped: DATABASE_URL is not set
```

## Vitest configuration

`passWithNoTests` was updated to `false` in `vitest.config.ts` for the `db` project since it is now seeded with specs.

## Validation / CI

A new job `db-tests` was added to `.github/workflows/ci.yml`. This job applies `database/bootstrap.sql`, runs migrations using `MIGRATION_DATABASE_URL`, executes `pnpm test:db`, `pnpm test:isolation`, and finally invokes the legacy runners (admin, ai-intelligence, acquisition).

*(CI run URL and job log excerpts will be observable on the PR push).*
