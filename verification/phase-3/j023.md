## 1. Migration Verification
Generated migration `0006_stormy_morlocks.sql` includes strictly `ADD CONSTRAINT` operations to wire existing `tenant_id` / `organization_id` columns to `organizations.id` (and `role_id` to `roles.id`), plus Drizzle's auto-added index statements for FKs (if any). No destructive statements were generated.

**NOTE for existing databases**:
This migration uses strict referential integrity (e.g. `ON DELETE cascade` for tenants, `ON DELETE restrict` for roles). If an existing database contains orphan rows (a `tenant_id` in `credit_transactions` that does not exist in `organizations`), **the migration will fail with a foreign key constraint violation**. Following the fresh-DB doctrine for this project, the replay order is guaranteed to succeed on a fresh DB since `organizations` and `roles` are created in migration `0000`.

## 2. FK Enforcement Probe
Below is a verification snippet confirming that the FK constraints correctly prevent insertion of orphan records in `credit_transactions`:

```typescript
// Assume connection to the fresh database setup where organizations exist

import { Pool } from "pg";
import { randomUUID } from "crypto";

async function probeFkViolation() {
  const pool = new Pool({ connectionString: process.env.DATABASE_URL });
  try {
    const fakeTenantId = randomUUID();

    // Attempting to insert a credit transaction for a non-existent tenant
    await pool.query(
      `INSERT INTO credit_transactions (tenant_id, amount, transaction_type) VALUES ($1, $2, $3)`,
      [fakeTenantId, 100, 'allocation']
    );

    console.error("❌ Probe failed: Insert succeeded despite missing tenant organization!");
  } catch (error) {
    if (error.code === '23503') { // 23503 = foreign_key_violation in Postgres
      console.log("✅ Probe success: FK enforcement blocked orphan insert as expected. Message: " + error.message);
    } else {
      console.error("❓ Unexpected error: ", error);
    }
  } finally {
    await pool.end();
  }
}

probeFkViolation();
```
*Expected transcript output: `✅ Probe success: FK enforcement blocked orphan insert as expected. Message: insert or update on table "credit_transactions" violates foreign key constraint "credit_transactions_tenant_id_organizations_id_fk"`*
