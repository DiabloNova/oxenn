# J-011: CI & Branch Protection Verification

This document outlines the manual steps required by the repository owner to enable branch protection, enforcing the newly added CI workflow.

## Owner Checklist

1. Navigate to the repository settings on GitHub: **Settings** > **Branches**.
2. Click **Add branch ruleset** (or edit an existing one for `main`).
3. Set the **Target branches** to include `main`.
4. Enable **Require a pull request before merging**.
5. Enable **Require status checks to pass before merging**.
   - Search for and select the `Build and Test` job from the CI workflow.
   - (Optional but recommended) Enable **Require branches to be up to date before merging**.
6. Save the ruleset.

## CI Workflow Summary
The added GitHub Actions workflow (`.github/workflows/ci.yml`) does the following on every PR and push to `main`:
*   Sets up Node.js 22 and pnpm using Corepack.
*   Caches the pnpm store for faster subsequent runs.
*   Installs dependencies using `pnpm install --frozen-lockfile`.
*   Runs static type checking via `pnpm typecheck`.
*   Runs linting via `pnpm lint`.
*   Builds the Next.js application via `pnpm build`.
*   Redundant runs on PRs are automatically cancelled.
