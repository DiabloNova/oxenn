# J-012 Build-time codegen containment (docsIndex)

## Option Chosen
Option A (preferred) was chosen. I kept the generated file `src/lib/docsIndex.ts` tracked in version control, but added a new CI step to enforce determinism. The CI step runs `git diff --exit-code src/lib/docsIndex.ts` after the build to fail if there's drift between the repository contents and the build output.

## Rationale
Option A is preferred because it allows the developer to easily see the auto-generated code and check the metadata directly in their PR (and it's explicitly stated as preferred in the prompt). Option B would involve updating path aliases globally and all importers, which is highly invasive for what is primarily a build artifact validation problem. By choosing Option A, we make sure that PRs containing documentation changes accurately reflect any meta-data changes synchronously, and the drift check enforces that developers don't forget to commit the changes.

## Generator Fix
The original generator code had a problematic escape sequence:

**Before:**
```javascript
const title = doc.title.replace(/"/g, '\\"');
const snippet = doc.contentSnippet.replace(/"/g, '\\"').replace(/\\/g, '\\\\').replace(/`/g, '\\`');
```

**After (Fixed):**
```javascript
const title = doc.title.replace(/\\/g, '\\\\').replace(/"/g, '\\"');
const snippet = doc.contentSnippet.replace(/\\/g, '\\\\').replace(/`/g, '\\`').replace(/\$/g, '\\$');
```
We also added escaping for `$`, which is crucial because the output generates JS code inside \` \` template literals, meaning if `\${var}` appeared in markdown, it would try to interpolate variables in the generator scope and crash at build/runtime. The original string replacement also escaped quotes when it wasn't necessary for template literals and did not escape backslashes *first*.
