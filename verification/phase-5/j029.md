# J-029: Privileged-path policy: enumeration, audit logging, AGENTS.md codification

## Overview

This step hardens the systemic risk created in J-028 (the implementation of explicit bypass capability for the tenant context manager) by explicitly listing, logging, and auditing all authorized privileged pathways in the codebase.

## Actions Taken

1. **Created Registry:** Created `src/core/database/privileged-paths.ts` housing the explicit registry mapped from tag values (e.g. `sys-login`) to documentation about valid tables read/written, calling module, and purpose justification.
2. **Updated Bypass Verification Logic:** Refactored `TenantContextManager.runWithSystemContext` in `src/core/database/tenant-context/index.ts` to strictly validate `purpose` tags against this exact registry list using `Object.hasOwn` to prevent prototype pollution. Additionally gated test-only tags against production environment usage. Any unregistered or invalid strings now fail explicitly via a `TenantContextViolationException`.
3. **Audit Log Emission:** Wired up `runWithSystemContext` to emit fire-and-forget insert queries into the global `audit_records` table, executing *after* the primary application transaction commits or rolls back to prevent application transaction abortion on audit logging failure. This covers both standard and nested system contexts for comprehensive trackability.
4. **Policy Enforcement:** Written rules around modifying or adding additional explicit pathways into the core `AGENTS.md` and explicitly mirrored the registry list in the more human-accessible `docs/security/privileged-paths.md`.
5. **Testing & Integrity Verification:** Generated `tests/unit/core/tenant-context/privileged-paths.test.ts` to enforce rejection logic for unknown paths and the query construction for both successful and error-based `audit_records` insertions.

## Security Assertions
* **Explicit Over Implicit:** Any system operation requesting privileged access must supply an explicitly listed string parameter; runtime evaluation strictly enforces this enum set.
* **Cost Efficiency / Stability:** The audit query insertion is intentionally executed via `.catch()` and fire-and-forget inside the leased client block. This prevents temporary database slowdowns in the logging pipeline from stalling or outright killing primary authentication routines.
