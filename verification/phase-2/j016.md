# J-016: Error-semantics sweep: infrastructure errors ≠ “Unauthorized”

## Overview
Replaced all broad catch blocks in Actions returning flatten `{success: false, error: "Unauthorized"}` strings to use typed error mappings for proper UI routing and security semantics.

## Mapping Table

| Original Code (Catch Block) | New Code (Error Mapping) | Resultant Object |
|---|---|---|
| `if (!session.user) throw new Error("Unauthorized");` | `if (!session.user) throw new AuthorizationError(401, "Unauthorized: No active session user.");` | `{success: false, error: "Unauthorized: No active session user."}` |
| `TenantContextViolationException` thrown | `return mapErrorToResult(err)` | `{success: false, error: "ServiceUnavailable", retryable: true}` |
| `DatabaseUnavailableError` thrown | `return mapErrorToResult(err)` | `{success: false, error: "ServiceUnavailable", retryable: true}` |
| `ZodError` thrown | `return mapErrorToResult(err)` | `{success: false, error: "BadRequest", details: [...]}` |
| Any default `Error` | `return mapErrorToResult(err)` | `{success: false, error: "InternalServerError"}` |
