### Limitations
- **Partial Mocking in Actions**: The server actions directly instantiate `new PostgresClient()` via `TenantContextManager`, bypassing the repository DI layer. Per `AGENTS.md`, DB connection unavailability throws a strict `DatabaseUnavailableError` that sanitizes outputs to "ServiceUnavailable". This prevents validating the pure payload (e.g., `{ pages: [] }`) at the very top level `result.result` boundary. The test thus validates that: (1) Repo logic correctly yields empty values and (2) The boundary safely handles the error context without crashing or fabricating mock data.
- **Testing Debt**: Future phases (e.g. J-038 Test Runner & DI refactor) should extract `TenantContextManager` DB logic into a mockable layer so actions return the full deterministic `{ success: true, result: { brand: null } }` object under test conditions.
